# Pokémon NEXUS — 실행 가능한 제작 계획

2026-09-22 재정립. 제작 순서는 이 파일 한 곳에서 관리한다. [현재 상태](PROJECT_STATE.md)의 정적 감사와 [비전·결정](NEXUS_GOAL.md), [기술 계약](DEVELOPMENT.md), [도시 제작 계약](MAP_STORY_DESIGN.md)을 입력으로 한다.

**전체 순서: 재정립 → 첫 배지 Vertical Slice → 신오 완주 → 관동 → 성도 → 하나 → 신오 귀환·최종장 → 고려·후일담.**
현재 RB1과 RB2 일부를 코드에 반영했다. 구현별 사실은 PROJECT_STATE를 따르며 QA 중단으로 단계 수용은 하지 않았다. 날짜 대신 산출물과 수용 조건으로 단계를 넘긴다.

## P0. 재정립 — 이번 문서 작업

- 기존 코드·자산·저장·채택 서사를 보존하고 정적 상태와 재사용/교체 근거를 정리한다.
- 기존 기준 파일을 통합하고 과거 기록의 권위를 제거한다. 새 00~06 체계를 병렬로 만들지 않는다.
- HYBRID와 아래 첫 제작 묶음·종료 조건을 결정한다.
- 문서 링크·일관성·공백·비문서 변경 보존만 확인한다. 이 단계 완료는 게임 구현 진척이 아니다.

## P1. 첫 배지 Vertical Slice

범위와 경험·MapId·수용 시나리오는 [FIRST_BADGE_SLICE](FIRST_BADGE_SLICE.md)가 담당한다.
기존 무쇠 작업을 활용하면서 새 게임부터 첫 승리와 귀환까지 연결한다. 첫 구간이 수용되기 전 신오 전역이나 여러 지방의 새 콘텐츠를 병렬 확장하지 않는다.

### RB1. 저장 보호와 이행 바닥

**코드 반영·실행 수용 대기.** 원문 보호·버전 판정·별도 활성 사본·복구 UI를 연결했다. 키와 실패 계약은 DEVELOPMENT §5를 따른다. 관련 파일: [engine](../src/engine.ts), [save](../src/save.ts), [save-library](../src/save-library.ts), [types](../src/types.ts), [main](../src/main.ts).

- 입력: 현행 v1 파서·worldRevision24·자동 저장 호출·대표 구형 저장의 조건. 실제 사용자 저장은 복사 없이 읽기/수정 대상으로 쓰지 않는다.
- 작업: 파싱 실패 원본을 격리하고 후속 자동 저장의 덮어쓰기를 막는다. 버전별 순수 이행과 활성 저장 전환 경계를 마련한다.
- 산출물: 정상/구형/손상/미래 버전별 처리표, 원본 보존과 복구 경로, 새 게임/기존 저장 분리, 실패 시 쓰기 방지 구현.
- 종료: 실제 사용한 키·슬롯·백업을 구별하고 실패해도 원본이 남는 계약이 코드로 연결됨. 재개 뒤 사본 복원 검사까지 통과해야 검증 완료.
- 제한: 이 작업에서 36배지 데이터·전투 엔진·전 지방 플래그를 일괄 교체하지 않는다.

### RB2. 첫 여정의 연결과 이벤트 등록

선행 RB1의 보호 경계 코드 반영. **201/잔모래 문 보존과 축복 시계 관찰 연결은 반영·미검증이며, 첫 구간의 기존 사건 등록 정리는 남아 있다.** 관련 파일: [unified-world](../src/unified-world.ts), [maps](../src/maps.ts), [explore-world](../src/explore-world.ts), [시계 모듈](../src/sinnoh-clock-story.ts), 중앙 이벤트·안내·표현 소비처.

- 201번도로의 호수 분기, 잔모래 센터/연구소 등 기존 문이 최종 통합 워프 덮어쓰기에서 보존되는지 고친다. 원본 배치와 최종 지도 조립을 구별한다.
- 시계 모듈의 설치·행동·프레임 갱신·그림·저장 읽기를 연결한다. 함수 정의만 있는 상태를 완료로 세지 않는다.
- 첫 구간의 이벤트만 맵/이벤트 등록, 조건, 상태 효과, 표현으로 나눈다. 기존 핸들러 어댑터와 순서를 유지한다.
- 산출물: 양방향 실제 경로·귀환표, 원고 장면→MapId→이벤트→소비처 대응, 구저장 위치 이행.
- 종료: 시작권역→201/호수→잔모래→202→축복→203/게이트→무쇠의 연결·실내·회복·귀환이 코드상 일관됨. 직접 보행은 QA 재개 후 확인한다.

### RB3. 신규 스타팅과 새 게임 도입

선행 RB1, RB2의 시작권역 경계. 디자인 추천은 [결정 대장](NEXUS_GOAL.md#아직-결정이-필요한-제품-사항)에 있다.

- 신규 사슴·늑대·물범의 첫 형태·이름·타입·초반 기술·표현·종 ID를 세 종 묶음으로 구체화한다. 디자인 결정과 수치 구현을 구별한다.
- 생성 입력·추출기·소유 허용·스타팅 판정·카탈로그·자산·학습표를 함께 연결한다. 포켓몬 전국번호나 기존 종을 재사용해 새 종으로 둔갑시키지 않는다.
- 가족·이름/외형 선택·엽서·챔피언 꿈·유진과 첫 관계를 실제 시작에 배치한다. 기존 town/lab의 역할과 떡잎/잔모래 목표 차이를 이행한다.
- 산출물: 신규 세 종의 최소 제작 카드, 새 게임 도입, 기존 저장의 기존 파트너 보존 경로.
- 종료: 새 게임 세 선택이 첫 여정에 필요한 포획·성장·기술·회복을 사용할 수 있음. 기존 저장에는 새종 강제 교환·배지 초기화가 없음.
- 기능 확인에 기존 3종을 임시로 쓸 수 있으나 신규 NEXUS 스타팅 수용으로 세지 않는다.

### RB4. 첫 배지까지 도시 경험 통합

선행 RB2·RB3. 도시 카드는 신오 지방 문서에서 하나씩 갱신한다.

1. 떡잎/시작권역·201·호수·잔모래: 출발과 발견, 실제 포획·동료 성장·센터/도구 준비.
2. 202·축복: 또래와 준비, 작은 세 초 징후. 주인공 접점 노출은 본편3장에 남긴다.
3. 203·무쇠게이트·무쇠: 탄갱의 강석과 현지 생태, 선택 실전·준비·관장전·첫 승리·유진과 밤·다음 길·귀환.

각 카드의 산출물은 맵·NPC·조우·트레이너·아이템·본편/독립 사건·재방문·저장·표현을 포함한다.
선택 광맥 관찰·특정 포획·모든 주민 대화는 새 필수 잠금으로 만들지 않는다.
전투 보강은 이 구간에서 쓰는 효과부터 한다. 미지원 상태이상·특성 등을 대사나 데이터에만 넣지 않는다.
강석전은 속도·우선도를 유지하고 신규 세 스타팅별 준비와 현지 선택지를 기준으로 팀·성장·보급을 조정한다.
종료는 도시 구현 완료 후보이며 QA가 중단된 동안 완료/PASS로 승격하지 않는다.

### RB5. 검증 기반 복원과 첫 구간 수용

**QA 명시적 재개가 필요한 단계.** 재정립 또는 일반 ‘계속’ 문구를 재개로 해석하지 않는다.

- 기존 검사 실패를 낡은 기대값/실제 계약 결함/환경 문제로 나눈다. 이름·치수 문구만 맞추려고 검사 전체를 삭제하거나 약화하지 않는다.
- 저장 원본 보호·이행, 출입/귀환, 취소·패배·보상 단발성, 전투/포획/PP에 필요한 검사를 먼저 복원한다.
- 구현이 끝난 무쇠 도시 묶음을 관련 검사·빌드·도시 여정·시각/음향으로 수용한다.
- 이어 새 게임부터 **신규 세 스타팅 각각** 첫 배지 뒤 귀환·저장/재접속까지 자연 진행한다. 준비 저장과 실제 성장 여정을 구별한다.
- 산출물: 계약 검사 결과, 자연 진행과 사본 이행 증거, 화면·음향 확인, 남은 결함 목록.
- 종료: [첫 구간의 두 수용 게이트](FIRST_BADGE_SLICE.md#7-두-개의-수용-게이트) 통과. 이때 처음으로 새 제작 기반이 입증된다.

QA 중단이 계속되면 구현 가능한 RB1~RB4를 진행하고 미검증 상태로 멈춘다. 수용 없이 다음 지방 확대를 자동 시작하지 않는다.

## P2. 신오를 하나의 게임으로 완주

입구 조건: P1 수용, 저장·진행·데이터 계약의 확장 가능성 확인.

- 꽃향기 방향의 서진 구호 만남과 본편3장 접점 노출부터 새 원고의 도시 순서로 이어간다.
- 신오 후반 네 체육관·사천왕·챔피언까지 확장한다. 기존 네 배지는 중간 성과다.
- 첫 리그까지 성장 곡선·레벨 범위·진화/학습·상태이상·아이템·필요 필드 이동을 도시 의존성에 맞춰 추가한다.
- 본편 사건·전설 행동·선택 연작·재방문을 도시 여행 중 제작한다. 체육관 뒤에 모든 사건을 몰지 않는다.
- 종료: 신오8배지·첫 리그·채택 필수 사건·현지 연작의 계획 범위, 실제 도입부터 리그/귀환·저장 수용. 관동 방문 동기가 플레이 안에서 성립한다.

P2 착수 시 신오 도시 카드만 상세화한다. 수백 도시 TODO나 모든 지방 수치를 지금 미리 고정하지 않는다.

## P3~P7. 이후 단계와 진입 조건

| 단계 | 제작 범위 | 핵심 의존·종료 기준 |
| --- | --- | --- |

각 지방에서는 도시+담당 도로/동굴을 완성하고 다음 도시로 간다. 기존 관동·성도·하나 코드와 자산은 보존하며 해당 단계에서 재채택한다.
선택 연작은 해당 지방 제작에 포함한다. 모두 P7로 미뤄 빈 여행을 만들지 않는다.
실제로 보고된 저장 손상·실행 불가 등 결함은 해당 영향을 우선 처리하되 이를 여러 지방 콘텐츠 확장의 명분으로 쓰지 않는다.

## 한 번의 작업을 끝내는 방식

현재 묶음의 입력·쓰기 파일·산출물·종료 조건을 정하고 독립 작업만 위임한다. 공통 저장/맵/엔진은 한 담당자가 통합한다.
끝나면 PROJECT_STATE의 해당 상태와 CONTINUE_STATE의 다음 위치만 갱신한다. 고유한 실패·검증 증거는 archive의 해당 통합 기록에 남기며 회차별 문서를 늘리지 않는다.
추가 계획 문서를 만드는 것으로 미완료 제작을 대체하지 않는다. 다음 구현은 RB2의 남은 첫 구간 등록 경계와 RB3 새 게임·신규종이다. RB1/2의 실행 검증은 QA 재개 후 수행하며 새 전체 계획을 다시 작성하지 않는다.

이전 계획의 채택 경위는 [결정 이력](archive/DECISION_HISTORY.md#record-story-axis-goal-20260920)에 남겼다. 현재 실행 순서는 이 문서만 관리한다.
