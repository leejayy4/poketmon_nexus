# 스토리 기준 구현 로드맵 — 넥서스를 어디까지 만들면 작품이 되는가

> **2026-09-21 서사 범위 갱신:** [새 본편 28장](NEXUS_STORY_COMPLETE.md)과 [연작](NEXUS_POKEMON_CHRONICLES.md)·[고려 4체육관](GORYEO_STORY_COMPLETE.md)을 적용한다. 아래 CH00~CH10의 플래그 수와 단계는 이전 구현의 조회 기록이며 새 원고 28장의 완료율이 아니다. 과거의 ‘신오 네 배지 출항·후속 권장 체육관’으로 구현 범위를 축소하지 않는다.

## 최신 원고를 실행 구조로 옮기는 순서

1. 기존 CH/SQ/PG ID·첫 파트너·네 배지까지의 저장·교통·재진입을 보존한 대응표를 만든다. 새 원고 장 번호를 저장 ID로 직접 치환하지 않는다.
2. 신오 기존 도입과 첫 네 배지를 연결하고 후반 네 배지·첫 리그까지 본편을 확장한다. 본편 출항 조건과 이미 이용 가능한 왕복 교통은 별도 조건으로 다룬다.
3. 관동·성도·하나 각각 8배지·첫 리그·현지 사건을 교차 배치한다. 체육관 뒤 사건을 몰아넣거나 첫 리그를 후일담으로 미루지 않는다.
4. 네 리그 완료 뒤 귀환·창기둥·깨어진세계·결말을 연결한다. 앞 지방에서 해결한 사건은 다시 실패한 것으로 되돌리지 않는다.
5. SQ·EX·생활 연작·재방문 변화를 해당 도시에서 함께 제작한다. 엔딩 후 고려는 네 거점·4체육관·대표 결승으로 구현한다. 본편과 고려의 완료 플래그는 분리한다.

현재 도시 작업과 기존 공통 시스템 보수는 계속 유효하다. 위 순서는 구현 설계이며 코드 반영·검증 완료나 QA 재개를 뜻하지 않는다.

2026-09-20 등록. [장기 Goal](NEXUS_GOAL.md)의 **스토리 축 실행 순서**를 정한다.

Goal의 범위·완료 판정·공통 시스템 번호(C1~)·지방 순서는 [NEXUS_GOAL](NEXUS_GOAL.md)이 단일 대장이다. 이 문서는 그 위에서 **「본편 CH00~CH10이 끊기지 않고 이어지는가」를 진척의 척도로 삼아** 장별 현황과 선행 조건을 관리한다. 두 문서가 충돌하면 NEXUS_GOAL을 따른다.

서사 내용은 [NEXUS_STORY_MASTER](NEXUS_STORY_MASTER.md), 실제 플래그·대사는 [STORY](STORY.md), 도시별 실행 요구는 [MAP_STORY_DESIGN](MAP_STORY_DESIGN.md), 도시 완료 조건은 [DEVELOPMENT 여섯 축](DEVELOPMENT.md#도시-하나의-완료-조건)을 따른다. 여기서 대사 전문·좌표·수치를 중복 보관하지 않는다.

**모든 QA 중단을 유지한다.** 아래 단계 정의는 구현 순서이며 QA 재개 지시가 아니다.

## 4. 잠가 둔 길 — 거절 문구를 약속으로

코드 전반에 이런 문장이 퍼져 있다.

- `파도타기 없이 건너지 않으며 서쪽 남서 구역과의 관통은 아직 경계다` (`johto-dark-cave-east.ts`)
- `현재 바위깨기·괴력을 새로 열지 않고 46번도로로 귀환한다` (같은 파일)
- `현재 수상 이동·낚시·특별 조우 구역은 아니다` (`blackthorn-city-layout.ts`)
- `건강한 동료를 선택해도 낚시·수상 이동·야생 조우·보상은 발생하지 않는다` (`fuchsia-life.ts`)

**하나하나는 옳은 절제다.** [루트 AGENTS](../AGENTS.md)의 `미구현 이동 수단·새 잠금·보상을 기능처럼 안내하지 않는다`를 지킨 결과이며 이 규칙은 계속 유효하다. 구현 전에 문구를 지우는 것은 금지다.

그러나 합계는 방향을 뒤집는다. 시리즈에서 물가와 바위는 **약속**이다. `지금은 못 가지만 반드시 다시 온다`가 여행의 동력이고 배지 구조의 엔진이다. 현재 넥서스에서 같은 물가는 **벽**이며 되돌아가라고 적혀 있다.

**제안 C10이 이 문제를 푼다.** 거절 문구가 달린 좌표들이 그대로 **개방 대장** 역할을 하므로, 파도타기를 구현하면 새 맵 0개로 이미 만든 장소 여러 곳이 동시에 살아난다. 회수하지 못한 좌표는 목록으로 남긴다.

## 7. 지금 착수 대상

**Phase 1의 스토리 작업이다.** C3가 완료됐으므로 남은 것은 C4 분류와 CH00~02다.

| 순 | 작업 | 산출물 |
| ---: | --- | --- |
| 1 | C4 — 로드 가능해진 검사의 실패를 **낡은 기대값 / 실제 회귀**로 분류 | 분류표. 수정은 사용자 판단 |
| 2 | CH01 3초 관측 이벤트 (축복·영원) | 관측 원본 저장 |
| 3 | CH01 서진 선의 조우 | CH09에서 읽을 기록 |
| 4 | CH02 관동행 선택 연결 | 기존 `researchDelivered` 계약 보존 |

1번을 **분류까지만** 하는 이유는 QA 중단 유지 때문이다. 로드조차 안 되던 상태는 [상세 AGENTS](AGENTS.md#검증과-도시-완료)의 `실행 불가`에 해당해 해소했지만, 개별 실패의 수정은 검증 재개 범위와 겹치므로 분류만 남기고 사용자 판단을 받는다.

이 스토리 축 작업은 [NEXUS_GOAL](NEXUS_GOAL.md)의 현재 도시(신오 무쇠시티)와 **병행 가능한 별도 축**이다. 도시 작업을 중단시키지 않는다.

## 8. 이 문서의 갱신 규칙

- 제1절 플래그 수치는 **측정 날짜와 함께** 갱신한다. 과거 값을 덮어쓰지 않는다.
- 단계 종료 조건은 충족 근거(회차 기록 링크)와 함께만 체크한다. QA 중단 중에는 코드 반영과 검증 완료를 구분해 적는다.
- 단계를 건너뛰어야 할 사유가 생기면 제2절 역산표에 근거를 추가하고 순서를 바꾼다. 근거 없이 순서만 바꾸지 않는다.
- 제3절 제안 C8~C12는 [NEXUS_GOAL](NEXUS_GOAL.md)에 채택되면 이 표에서 제안 표시를 지우고 그쪽 번호를 인용한다.
