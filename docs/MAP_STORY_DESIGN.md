# 도시 콘텐츠 제작 계약

> 분류: **확정 기준** · 재정립일: 2026-09-22. 이 문서는 도시를 실제 플레이로 완성하는 절차와 산출물을 관리한다.
> 현재는 **첫 여정의 실제 구현 단계**다. QA 중단의 운영 지시와 재확인 근거는 [개발 계약](DEVELOPMENT.md#1-책임과-적용-범위), 허용된 정적 검토와 실행 제한은 [검증 규칙](AGENTS.md#검증과-도시-완료)을 따른다. 구현 착수를 QA 재개로 해석하지 않는다.

제작 순서는 [STORY_AXIS_ROADMAP](STORY_AXIS_ROADMAP.md), 현재 구현 사실과 협업 상태는 [PROJECT_STATE](PROJECT_STATE.md), 기술 구조와 호환 계약은 [DEVELOPMENT](DEVELOPMENT.md)를 따른다.
채택 서사는 [NEXUS_MAIN_STORY_CANON](story/NEXUS_MAIN_STORY_CANON.md)을 기준으로 해당 원고를 읽는다. 이 문서는 새 사건·보상·지역 잠금을 승인하지 않는다.
이전 지방별 사례·구현 로그·옛 우선순위는 [재정립 전 원문](archive/2026-09-22-rebaseline/MAP_STORY_DESIGN.md)에 보존한다. 과거 로그의 다음 작업을 현재 배정으로 사용하지 않는다.

## 1. 제작 단위와 작업 카드

제작 단위는 **도시 또는 마을 하나와 그 경험에 필요한 진입·탐험·출발 구간**이다.
도로·동굴·숲·실내를 별도 완료 경쟁 대상으로 늘리지 않는다. 공유 구간은 한 도시가 맡고 실제 출입구 또는 분기점을 인계 경계로 정한다.
시작권역부터 첫 배지까지의 대표 플레이 구간(Vertical Slice)은 여러 도시 카드를 잇는 수용 목표이며 도시별 제작 책임을 대신하지 않는다.

작업 카드는 담당 지방 문서의 해당 도시 절을 갱신해 작성한다. 새 회차 문서를 기본 산출물로 만들지 않는다.

| 항목 | 반드시 적을 내용 |
| --- | --- |
| 목적·서사 | 온 이유, 채택 원고의 장·장면, 필수 본편과 선택 활동, 플레이어가 바꿀 결과 |
| 경계 | 직전 거점, 담당 도시·실내·경유 맵, 다음 출구, 공유 구간의 담당 경계 |
| 재사용 판단 | 기존 코드·자산·데이터별 그대로 사용/보수/교체/보류와 이유 |
| 의존성 | 이번 경험에 필요한 공통 기능, 이미 지원하는 범위, 미지원 기능의 처리 |
| 실행 연결 | MapId, 이벤트 ID, 조우 풀, 트레이너, 상태 읽기/쓰기, 렌더러·안내 소비처 |
| 지속성 | 저장 이행, 취소·패배·재방문, 보상 중복 방지, 실제 동료 식별 |
| 종료 조건 | 필수 산출물, 남은 결함, 구현 근거와 필요한 검증 근거 |
| 다음 인계 | 다음 도시·연결 경계·남은 공통 문제와 현재 상태 문서 링크 |

상세 좌표는 [WORLD_ROUTES](WORLD_ROUTES.md), 현재/목표 크기는 [MAP_SIZE_STANDARDS](MAP_SIZE_STANDARDS.md)의 해당 행을 참조한다.
동일한 수치·출구 표를 여러 문서에 복제하지 않는다. 현행 코드와 불일치하면 어느 쪽이 목표인지 먼저 표시한다.

## 2. 제작 단계와 종료 조건

아래 단계는 제작 의존 순서다. 단계마다 전체 테스트나 브라우저 검사를 반복하는 절차가 아니다.
필수 경로를 방해하는 미지원 시스템이 있으면 해당 공통 작업을 먼저 연결하고, 관련 없는 시스템 완성을 기다리며 도시 제작을 미루지 않는다.

| 단계 | 입력 | 산출물 | 단계 종료 조건 |
| --- | --- | --- | --- |
| 1. 조사 | 채택 서사, 기존 도시 코드, 필요한 원작 자료 | 출처 기록과 재사용/보수/교체 목록 | 원작 사실·프로젝트 재구성·미확인이 구분됨 |
| 2. 범위·인과 | 조사 결과, 본편·독립 이야기의 역할 | 도시 카드, 필수/선택 행동과 전·중·후 상태 | 방문 이유→행동→결과→다음 여행의 인과가 설명됨 |
| 3. 공간·연결 | 도시 카드, 지리·크기 대장 | 외부·필수 실내·담당 도로/동굴, 양방향 출구 명세 | 보이는 길·충돌·조사 위치·안내가 같은 경로를 사용함 |
| 4. 콘텐츠 | 공간, 실제 지원 카탈로그 | NPC·대화·조우·트레이너·보급·사건·선택 활동 | 배치와 문구가 실행 이벤트·전투·포획·보상 소비처에 연결됨 |
| 5. 상태·지속 | 이벤트와 개체·저장 계약 | 취소·패배·재방문·복원·중복 방지 처리 | 정상 진행 이외의 경로와 이전 유효 기록의 처리도 명세·구현됨 |
| 6. 표현 통합 | 실제 공간·행동·상태 | BW·BW2풍 화면·동작·전투/사건 연출·음향 연결 | 필수 경험에 필요한 표현이 등록되고 임시 표현의 남은 범위가 명시됨 |
| 7. 수용 | 모든 필수 구현과 사본 저장 계획 | 도시 단위 검증 근거, 결함 처리, 다음 인계 | QA 재개 후 필요한 검증을 통과하고 필수 누락·알려진 진행 결함이 없음 |

코드에 정의만 추가하고 등록·호출하지 않은 산출물은 단계 종료로 인정하지 않는다.
단계 3~6의 구현 연결 근거는 실행 검증을 대신하지 않는다. QA 중단 중에는 **도시 구현 완료 후보·QA 대기**까지만 기록할 수 있다.

## 3. 원작·외부 자료 적용 기록

[REFERENCE_RESEARCH](reference/REFERENCE_RESEARCH.md)의 목적별 참고군을 도시 조사와 개발 검토에 적극 활용한다. 기존 유효한 기록은 재사용하고 버전·범위가 달라진 부분을 갱신한다.
장소 작업은 Bulbapedia·Serebii의 해당 장소, 진행·길막은 StrategyWiki/GameFAQs, 원작 연결·이벤트는 해당 pret 소스를 대조한다. 관련 구조 판단이 있으면 시스템별 참고 저장소까지 확인한다. 매번 모든 자료를 열 필요는 없지만, 목록만 붙이거나 기억만으로 조사 완료를 선언하지 않는다.
원작과 다른 넥서스 구성이 더 적합하면 변경 이유와 플레이·저장 영향을 적어 채택한다. 직접 복사하는 경우에는 출처·파일·commit/version·라이선스를 별도로 확인한다.

| 기록 필드 | 내용 |
| --- | --- |
| 대상 | 지방·도시·도로/동굴·MapId·이벤트 ID |
| 출처 | 정확한 URL 또는 파일, 확인일, 게임 버전, 코드의 commit/tag |
| 확인 사실 | 실제 열람한 본문·지도·데이터가 뒷받침하는 내용 |
| 현재 차이 | 관련 코드 경로와 원작과의 구체적 차이 |
| 적용 결정 | 원작 반영 / 넥서스 재구성 / 미채택과 이유 |
| 실제 연결 | 수정 대상과 생성기·이벤트·렌더러의 소비처, 미연결 여부 |
| 관련 기준 | 서사·지리·크기·실행 데이터 기준의 해당 절 |
| 상태 | 자료 확인 / 설계 / 코드 반영 / 실행 검증을 구분 |
| 재사용 | 코드·자산 재사용 여부, 재사용한 원본 파일·버전·라이선스 |

접근 실패·미열람은 미확인이다. 검색 요약이나 사이트 이름만으로 자료 확인을 기록하지 않는다.
기존 접근·표시 오류는 원작을 다시 조사하지 않고 보수할 수 있으며, 이때는 프로젝트 오류 수정으로 기록한다.

## 4. 공간·여행·생태 연결

장소마다 공식 이름, 프로젝트 표시명, 설계 노드, 실제 MapId, 기존 저장 별칭을 구분한다.
원작 번호·고유명은 [WORLD_ROUTES](WORLD_ROUTES.md)를 따르며 이름만 바꾼 축약 통로를 원작 지리 복원으로 표시하지 않는다.

- 연결에는 출발 MapId·출구 좌표/진입 방향, 도착 MapId·안전 도착점/방향, 실제 경유 순서, 수단·조건·귀환을 함께 적는다.
- 일방 통행은 의도와 돌아오는 수단을 명시한다. 미개통 구간이나 계획한 맵은 현재 이용 가능한 경로처럼 안내하지 않는다.
- 현재/목표 가로×세로, 층별 역할은 크기 대장에 한 번만 기록한다. 일괄 정사각형·면적 증가를 완성 기준으로 쓰지 않는다.
- 지형 변화·랜드마크·분기·휴식·출구 예고가 여행의 흐름을 만든다. 모든 빈칸을 이벤트로 채울 필요는 없다.
- 벽·절벽·물·조우 구역의 그림은 실제 충돌·지형과 일치해야 한다. 그림으로 문·조사 접근점·안전 본선을 가리지 않는다.
- 보행, 조사물, 필드/전투 painter, 미니맵, 개발 지도, 목적지 안내, 방문 기록이 실제 장소와 이벤트를 공유해야 한다.
- 조우는 실행 카탈로그의 지원 종·방법·시간·레벨·가중치로 연결한다. 물 그림만으로 낚시·수상 조우를 지원한다고 쓰지 않는다.
- 현지 포획·성장·편성·회복·선택 전투가 도시 경험으로 이어지게 한다. 선택 포획이나 생활 활동은 승인 없이 본선 통행 조건이 되지 않는다.

종·기술·아이템 효과를 지방별로 복제하지 않으며 생성 원본과 실행 소비 경로는 [RUNTIME_DATABASE](RUNTIME_DATABASE.md)를 따른다.

## 5. 서사·동료·저장 계약

새 원고의 장 번호와 기존 `CHxx`·`SQxx`·설계 노드·실행 플래그는 서로 다른 식별자다.
원고 항목마다 기존 실행 이벤트와의 대응을 적고, 대응이 없으면 **미연결**로 둔다. 번호가 같다는 이유로 완료를 승계하지 않는다.
본편·전설·독립 포켓몬 이야기·선택 생활 활동의 완료 상태를 분리한다. 기존 생활 기록을 새 본편 사건의 증거로 바꾸지 않는다.
실행 플래그와 조건·보상 시점은 [STORY](STORY.md), 저장 구조·이행은 [DEVELOPMENT](DEVELOPMENT.md)에 연결한다.

- 사건마다 시작 조건, 실제 행동, 상태 확정/저장 시점, 보상, 재실행 조건, 끝난 뒤 대화·환경·다음 목적지를 정의한다.
- 대화·전투·워프 중단 또는 오래된 콜백이 뒤늦게 실행돼 이미 바뀐 상태를 완료하거나 보상을 중복 지급하지 않도록 한다.
- 같은 동료가 성장하고 귀환하는 활동은 **선택한 실제 개체**를 추적한다. 종·이름·레벨이 같은 다른 개체를 대체 증거로 삼지 않는다.
- 파티 순서 변경, PC 보관·인출·직접 교체, 진화, 기절·회복 때 같은 개체와 활동 단계가 어떻게 유지되는지 적는다.
- 같은 동료 재선택은 유효한 진행을 보존한다. 다른 동료로 바꿀 때 초기화 범위를 먼저 알리고 취소 시 기존 기록을 유지한다.
- 과거 저장에 종만 남아 있으면 특정 개체의 완료로 꾸미지 않는다. 과거 유효 기록을 남기고 새 개체 선택·이행 정책을 명시한다.
- 패배·도주·취소·재방문이 성공으로 기록되지 않아야 한다. 완료 후 반복 행동과 일회성 보상 처리를 구분한다.
- MapId·출구·회복점 변경은 이전 위치, 포획 출처 `met`, 방문·안내 기록과 저장 별칭의 이행까지 다룬다.

새 개체 ID나 범용 퀘스트 엔진이 필요하면 기술 계약에서 판단한다. 모든 지역 모듈을 일괄 재작성하는 것을 도시 착수 조건으로 삼지 않는다.

## 6. 증거와 도시 완료

상태는 `범위 정리 → 구현 중 → 통합 중 → 구현 완료 후보·QA 대기 → QA 보완 중 → 도시 완료`로 기록한다.
문서·데이터·맵·자산의 존재와 등록 개수는 구현 완료율이나 플레이 수용의 증거가 아니다.

| 근거 | 증명하는 범위 | 대신할 수 없는 근거 |
| --- | --- | --- |
| 코드·차분 읽기 | 정의·소비 경로·의도한 상태 처리 | 실제 실행 성공·저장 안전성 |
| 자동 검사·타입/빌드 | 실행한 검사 범위·컴파일/묶음 생성 | 자연 진행·화면·음향·도시 경험 |
| 준비 사본 저장 플레이 | 특정 상태·실패 분기의 재현 | 시작부터 그 상태에 도달할 수 있는지 |
| 자연 진행 | 직전 거점부터 보행·성장·사건·출발의 연속성 | 다른 파티·선택지·미방문 분기 전부 |
| 시각 확인·음향 청취 | 실제 출력의 가독성·가림·연출·들린 소리 | 저장·진행·전투 규칙의 전체 정확성 |

도시 수용은 직전 거점→담당 진입 구간→도착/보급→필수 사건·시설→포획/육성/전투→다음 출구→귀환을 확인한다.
적용 범위의 취소·패배 복귀·동료 상태 변화·이전/새 저장 재접속, 화면·음향을 함께 다룬다. 사용자 실제 저장 대신 구분된 QA 사본을 사용한다.
실패를 고친 뒤에는 영향 항목을 재확인한다. 이미 유효한 증거는 근거 없이 반복하지 않으며 미확인·도구 실패는 그대로 남긴다.
**모든 필수 구현과 필요한 수용 근거가 갖춰졌을 때만 도시 완료**다. QA 중단은 구현 누락의 면제가 아니며 검증 없이 완료할 허가도 아니다.
