# 네 지방 공통 데이터·세계관 기준

> 적용 우선순위: [개발 기준 제0절](DEVELOPMENT.md#0-최우선-목표와-지방도시-작업-단위)의 포켓몬 세계관·DP풍 맵/스토리와 지방→도시 단위 목표를 따른다. 검증은 [도시 구현 완료 후 QA](AGENTS.md#검증과-도시-완료)에 모은다. 이 문서의 데이터·현재 경로·원작 비교는 도시 구현의 근거이며 별도 QA 주기나 과거 첫 배지 우선 지시가 아니다.


검토일: 2026-09-09. 적용 지방: 신오·관동·성도·하나. 이 문서는 기존 설계 DB를 함께 쓰는 기준과 현재 코드의 차이를 기록한다. 아래 논리 테이블은 SQL 서버 도입이나 새 게임 기능의 구현 선언이 아니다. 현재 저장소는 TypeScript 객체·JSON·브라우저 저장을 사용한다.

함께 읽기: [DB 안내](개발용_데이터베이스_안내.md) · [장소·도로·교통](WORLD_ROUTES.md) · [개발 계약](DEVELOPMENT.md) · [이야기·플래그](STORY.md).

## 1. 공통 원칙과 자료 우선순위

1. **종·기술·타입·아이템의 기본 규칙은 네 지방이 공유한다.** 지방마다 같은 피카츄나 같은 기술을 별도 정의하지 않는다. 지방 차이는 서식지·입수처·상점 재고·트레이너 편성·환경·시설에 둔다.
2. 원작 참고 사실, 사용자 확정 설정, 프로젝트 재구성, 현재 구현, 직접 검증을 구분한다. 원작 표에 존재하거나 `implemented: true`인 종이라고 포획·기술·진화·그림·저장이 모두 구현된 것은 아니다.
3. 현재 동작은 관련 소스와 저장 계약으로 확인한다. 확정 이야기·변경 권한은 STORY와 최신 사용자 지시, 공통 데이터 정책은 이 문서, 장소 연결은 WORLD_ROUTES, 제작 후보 수치는 `nexus-plan.json`과 생성 DB를 따른다. 충돌 시 초안으로 현재 저장·진행을 덮어쓰지 않는다.
4. DP/플라티나풍은 시각·조작 기준이다. 데이터까지 전부 4세대라는 뜻은 아니다. 현재는 **플라티나 기술 습득표 + 고정 PokéAPI 스냅샷의 타입·위력·상성 + 프로젝트 전투 규칙**의 혼합이다. 세대·버전이 다른 값을 암묵적으로 섞거나 ‘원작 완전 재현’으로 쓰지 않는다.
5. 새 지방에 들어가도 파티·박스·도감·기술·돈·도구·이미 획득한 배지를 초기화하지 않는다. 체육관·교통·조우 개방을 단순 지방 방문이나 초안 CH 번호와 자동 연결하지 않는다.

원자료는 [출처 명세](design-data/source-manifest.json)의 고정 커밋 `d4f9a4af58ade123fbc0558f68b1c69daa97d9e4`다. 한국어 표기는 [포켓몬코리아 도감](https://www.pokemonkorea.co.kr/pokedex), 대량 데이터 구조는 [PokéAPI 원본](https://github.com/PokeAPI/pokeapi/tree/d4f9a4af58ade123fbc0558f68b1c69daa97d9e4/data/v2/csv)을 참조한다. PokéAPI는 커뮤니티 자료이며 전체 행을 공식 개별 검증했다는 뜻은 아니다. 원작 버전별 조우 근거를 프로젝트의 등장 확률로 그대로 해석하지 않는다.

## 3. 세계관과 데이터의 일관성

- 생태: 숲·동굴·습지·설원·바다 등 실제 지형과 조우 방법을 맞춘다. 물이 그려졌다고 낚시/파도타기 조우가 구현된 것은 아니다. 현재 낮 풀만 사용하는 곳에서 밤 전용 종을 있다고 안내하지 않는다.
- 성장: 진화 조건·학습 레벨·보유 TM·선택 기술 수를 함께 검토한다. 조건 미지원 시 다른 진화로 임의 대체하지 않는다. 현재 Lv25 상한 밖 진화를 가능하다고 안내하지 않는다.
- 획득: 야생·선물·교환·진화의 출처를 유지한다. 상록숲 야생 피카츄와 연구소 피카츄 선물은 별개다. 야생 반복 포획 허용과 선물 1회 제한을 섞지 않는다.
- 전투: 표시 위력·설명·실제 피해·상성 미리보기는 같은 규칙을 사용한다. 독침의 직접 피해만 지원하면서 독 부여를 광고하거나, PP 소비/선공이 없는 기술에 이를 구현된 효과처럼 쓰지 않는다.
- 생활: 포켓몬센터 회복, 상점 보급, PC 편성, 도감 관찰, 기술 준비가 다음 여행으로 이어지게 한다. 설명용 전시관과 실제 서비스를 구분한다.
- 교통: 원작의 바다를 도보 도로로 축약한 경우 현재 재구성임을 표시한다. 번호를 붙이는 문서 작업만으로 수상 이동 기술·티켓·요금·배지 잠금을 새로 만들지 않는다.
- 이야기: 신오→관동→성도→하나→신오 귀환이라는 확정 큰 순서와 CH별 잠금 초안을 분리한다. 박사·라이벌·조직·전설 사건·교환 서비스·리그 조건은 기존 확정 범위에서만 사용한다.

## 5. 수정·검토 절차

1. 대상 테이블·ID·지방·장소와 현재 소비 코드를 찾는다. 전체 표를 매번 읽지 않고 관련 종/기술/아이템/구간의 부모·자식 참조까지 본다.
2. 배치·가격·팀 제안은 `docs/design-data/nexus-plan.json`, 문서 설명은 생성기의 해당 렌더러에서 수정한다. 생성 출력만 고치지 않는다. 수작업 기준인 이 문서와 WORLD_ROUTES는 직접 수정한다.
3. 전체 설계 변경 시 `python -X utf8 scripts/design/build_databases.py`, 런타임 적용 요청이 있는 해당 범위만 `python -X utf8 scripts/design/export-runtime-pokemon.py`로 추출한다. 자산이 필요할 때만 `--assets`. 문서 검토만으로 추출·게임 데이터·저장을 바꾸지 않는다.
4. 참조 ID 유일성, 존재하지 않는 종/기술/도구/맵, 풀 가중치·레벨, 습득/진화 조건, 구매·소모·보상 중복, 왕복 출구를 변경 범위에서 확인한다. 전체 생성 DB의 `validation.json`은 설계 참조 검사이며 플레이 합격표가 아니다.
5. 문서 변경은 링크·수량·현재 경로 대응·생성 설명의 재현·diff를 검사한다. 게임 변경의 검증은 AGENTS의 도시 완료 후 QA와 실제 오류의 최소 확인 기준을 따른다.

## 6. 이번 보완과 남은 결정

기존 7종 DB의 내용과 생성 원본을 검토했다. 누락된 공통 관계·지원 수준·지방/맵/교통 참조를 이 기준으로 보완하고, 오래된 DB 안내·도감·기술 안내 수량을 정리했다. 원작 수치 행·창작 배치·현재 파티는 변경하지 않는다.

2026-09-10 후속 기준: 공식 번호·고유명은 [WORLD_ROUTES](WORLD_ROUTES.md), 지도 전환·도시별 역할은 [MAP_STORY_DESIGN](MAP_STORY_DESIGN.md)을 따른다. 프로젝트 번호는 내부 이행 키다. 하나는 B2W2 지리 기준이며 물풍경–궐수의 6번도로/전기돌동굴, 모란만–구름 선박은 후속 전환 목표다. 새 본편·교통 잠금은 별도 결정한다.

[REFERENCE_RESEARCH](REFERENCE_RESEARCH.md)에 자료별 역할·확인 버전·접근 한계와 조우 조사 필드를 기록했다. API 장소 관계에서 워프·스토리 해금을 추론하지 않는다. 현재 저장의 포획 출처 `met`는 과거 기록으로 보존하고 공식명 이행 시 조회 별칭을 둔다. 앞선 데이터 수량은 작성일 스냅샷이며 최신 지도 수량은 MAP_STORY_DESIGN 제1절을 따른다.
