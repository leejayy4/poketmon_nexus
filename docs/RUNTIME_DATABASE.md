# 포켓몬 넥서스 공통 실행 데이터 구조

## 211번도로 실행 카탈로그 확장 — 2026-09-13

방울랑433·동미러436을 포함한 실행 소유 가능 종은56종, 조우풀은49개다. 지역 원본 `scripts/design/runtime-local-pools.json`에서 서부 S-R211-WEST와 동부 S-R211-EAST를 생성하며 `runtime-encounters.ts`의 각 MapId가 소비한다. 원작 Pt 낮 출현과 프로젝트 레벨/제외종 차이는 각 source 레코드에 기록했다. 새 종의 전후면 이미지는 기존 고정 출처 exporter로 생성했고, 진화·특성·미지원 기술 효과를 추가한 것은 아니다. 생성 절차만 수행했으며 포획·성장·저장 QA는 미실행이다.

## 최신 전투 적용 — 2026-09-13

`battle.ts`의 공통 피해 계산은 종별 공격/방어 또는 특수공격/특수방어와 레벨·기술 위력을 사용한다. 기술 category는 기존 고정 PokeAPI 스냅샷의 moves.csv damage_class_id에서 가져오며 exporter에도 같은 필드를 추가했다. 기술 설명에 물리/특수/변화를 표시한다. 자속 1.5배와 기존 상성을 적용하고 공격 하락·방어 상승/하락은 물리 계산에만 적용한다. 고정40/레벨 피해와 타입 무효, 발버둥의 상성·자속 제외는 유지한다.

참고: [Showdown 피해 계산 소스](https://raw.githubusercontent.com/smogon/pokemon-showdown/master/sim/battle-actions.ts), 2026-09-13 조회. 원작 계열의 레벨·공격/방어·위력 계산 구조와 물리/특수 분리를 참고한 프로젝트 부분 구현이다. IV/EV는0, 성격 보정은1로 계산하며 저장된 성격에 수치 효과를 부여하지 않는다. 기존 HP 성장과 단계 상한3은 유지한다. 피해 난수·급소·PP·명중·특성·소지품을 구현한 것이 아니며 원작 완전 재현이 아니다. 피해 예측·플레이어·상대 AI가 같은 함수를 사용한다.

QA 중단으로 테스트·타입 검사·빌드·브라우저·저장 검증은 미실행이다. 기존 수치 기반 테스트 기대값과 체육관/도로 난이도는 QA 재개 시 재평가해야 하며 단순 수치 갱신으로 통과 처리하지 않는다. 아래 과거 피해 계산 미지원 설명은 이 변경 전 상태다.

2026-09-12 · 구조 v1 · **코드 연결 완료, QA 중단으로 미검증**. 네 지방이 같은 정의를 공유하고 지역별 배치·파티·사건 상태를 분리하는 기반이다. 전체 도감·모든 효과·본편 퀘스트가 구현됐다는 뜻은 아니다.

## 3. 실제 동작 연결과 호환

- pokemon.ts, growth.ts, growth-preview.ts, battle.ts, runtime-encounters.ts의 JSON 접근을 공통 runtime.ts로 모았다. 기존 공개 상수/함수 이름은 유지한다.
- 상점의 순서는 몬스터볼→상처약, 각각200원이다. 가방 키 pokeBalls/potions, IT ID와 구매 안내가 같은 아이템 정의를 읽는다.
- 상처약은 기존20HP 회복이며 부활시키지 않는다. 몬스터볼은 기존 ‘적 HP 절반 이하에서 성공, 그 외55%’의 단순 프로젝트 규칙을 정의로 옮겼다. 원작 포획률 공식 구현으로 표시하지 않는다.
- RUNTIME_RULES는 현재 레벨25·박스60·기술4·가방999·구매99 등 지원 한계를 기록한다. 육성 상한·박스/기술 상수·상점 수량 제한을 연결했다. 모든 UI/저장 상수의 일괄 이행이나 장기 레벨68 지원을 완료한 것은 아니다.
- WORLD_DATABASE는 지도 생성 후의 현재 정의를 지연 조회한다. getMap의 수집물 제거·전기돌 상태·통행 플래그·NPC 위치 처리는 그대로 호출별 적용한다. 가변 저장 상태가 카탈로그에 캐시되지 않는다.
- 일반 왕복 교통·MapId 별칭·이전 포획 장소·승리 기록·저장 버전은 변경하지 않는다. 지역과 원작 번호를 맵 이름에서 자동 추측하지 않는다.

## 4. 스토리 조건과 보상 경계

StoryCondition은 flag/badge/all/any/not의 선언형 조건이다. meetsStoryCondition은 조건을 읽으며 보상을 지급하거나 진행을 바꾸지 않는다. 기존 숫자/불리언 플래그의 참/거짓 해석을 보존한다. 현재는 adventure-guide의 관측 자료 받기→전달→조사선 목표만 이 구조에 연결했다. 앞선 파트너·출발·네 배지 판단과 이후 지역 탐험 안내는 유지한다.

지역별 후속 본편은 채택된 NEXUS_STORY_MASTER v2에서 도시별 단계·행동·결과를 구체화한 뒤 별도 실행 핸들러로 연결한다. 범용 퀘스트 상태 저장·트랜잭션 보상 엔진·모든 지역 사건 자동 등록은 이번 구현 범위가 아니다. 기존 사건 보상은 기존 핸들러의 중복 지급 방지를 보존한다.

## 5. 원작·프로젝트·지원·검증 구분

RUNTIME_ORIGIN은 원본 커밋과 혼합 데이터 출처를, 종 레코드는 기본 습득 버전과 BW2 예외를 제공한다. ITEM_ORIGIN은 기존 프로젝트 효과·가격임을 명시한다. implementation=runtime은 코드에 연결되었다는 뜻이며 verification은 not-verified-by-catalog다. BW·BW2풍 목표가 모든 기술·전투 규칙의5세대 전환을 뜻하지 않는다.

inspectRuntimeReferences는 종의 기술, 진화 양 끝 종, 조우 종/소유 가능 여부, 레벨 범위·가중치 누락을 반환하는 **명시 호출용 제작 진단**이다. 시작·플레이·import 시 자동 실행하지 않고 이번에도 호출하지 않았다. 지도 출구·원작 지리·스토리 그래프·보상·저장·게임성의 검증을 대신하지 않는다.

## 6. 후속 지방 구현 절차

1. 현재 도시에서 필요한 공통 종·기술·아이템이 실행 카탈로그에 있는지 코드로 확인한다. 미지원 효과는 현재 지원이라고 표시하지 않는다.
2. 원본/추출기에 수치와 지원 범위를 정의하고 지역별 풀 node·MapId 바인딩·트레이너 행을 추가한다. 공통 데이터의 지방별 복사본을 만들지 않는다.
3. 도시 전/중/후 상태·필수/선택 전투·포획/육성 공급·다음 출구·귀환을 연결한다. 전체 설계 DB를 일괄 import하지 않는다.
4. 실제 구현 기록을 도시 인계에 남기며 미검증 상태를 유지한다. 사용자 재개 전 모든 테스트·타입·빌드·브라우저·저장·시각/음향 QA는 중단한다.

주요 남은 확장: 능력/기술 효과 전체 지원, 별도 지역·장소 메타데이터의 명시적 바인딩, 일반화된 사건/보상 저장 엔진, 자산/애니메이션 카탈로그, 장기 성장·경제. 현재 기반을 도시별로 실제 사용하며 확장한다.

## 최신 행동 순서 — 2026-09-13

공통 battleTurn의 기술 대결은 runtime 기술 priority, 종별 speed와 레벨로 계산한 속도, 동률일 때 주입된 random의 50% 판정 순서로 처리한다. IV/EV·성격·상태이상·특성에 의한 속도 보정은 미지원이다. 상대는 턴의 기술 선택 시 한 번만 기술을 고르며 플레이어 행동 결과를 보고 같은 턴에 기술을 바꾸지 않는다. 선공으로 기절·승패·교체가 발생하면 그 턴의 남은 기술을 실행하지 않는다. 교대·도구·도주는 기존 별도 처리를 유지한다.

참고: [Showdown 행동 정렬](https://raw.githubusercontent.com/smogon/pokemon-showdown/master/sim/battle.ts)의 comparePriority/speedSort, 2026-09-13 조회. 전체 세대별 행동 큐 재현이 아닌 현재 단일 전투의 부분 적용이다. 기술 설명에 비영 우선도를 표시한다. 테스트·빌드·브라우저·저장 QA는 중단 유지로 미실행이며 선공/후공의 기절·반동·흡수·방어·다음 상대 등장 및 기존 난수 테스트의 재검토가 남는다.

## 특별 개체 전투·색상 — 2026-09-13 구현 계약

`battle.ts`의 `createSpecialBattle(save, {eventId, species, level, met, allowCapture, shiny?})`는 기존 지도 조우표와 별도로 상대를 생성한다. 활성 동료가 없거나 지원 종/레벨/포획 가능 종 계약에 맞지 않으면 null이다. 지역에서는 현재 사건 조건과 중복 포획을 확인한 뒤 호출한다. 일반 야생 조우표를 바꾸거나 트레이너 전투로 위장하지 않는다.

- 진정전과 선택 포획은 서로 다른 eventId를 사용한다. 포획 금지 전투에서 볼 선택은 아이템 소비 전에 거절한다.
- engine은 실제 전투 종료에서 `specialBattleResultFlag(eventId, outcome)`에 true를 저장한다. outcome은 won/caught/escaped/lost이며 누적 결과를 덮어쓰지 않는다. 마지막 결과 `specialBattle:<id>:last`는 각각 1/2/3/4다. 패배는 회복 체크포인트 이전에 기록된다.
- 지역 진정 완료는 해당 진정전 won, 포획 소유 결과는 선택 포획 caught를 읽는다. 도주·패배·전투 중 저장·복귀는 완료가 아니다. 공통 API 자체가 CH04 상태를 기록하지 않는다.
- `Pokemon.shiny?:boolean`은 없는 경우 일반 개체다. 현재 특별전투 API와 전후면 자산의 붉은 변형 지원은 종130에 한정된다. 포획·스냅샷은 개체 복사로 이 속성을 유지하며 저장은 boolean을 검사한다.
- 종130은 기존 exporter의 고정 CSV/설계DB에서 능력치·지원기술을 생성하며 ownable에 포함한다. 일반 조우 슬롯과 잉어킹 진화는 추가하지 않았다. 붉은 전후면은 같은 고정 sprites commit의 BW 자산이고 URL/hash는 `public/assets/pokemon-runtime-sources.json`에 기록한다.

현재는 코드·데이터·자산 연결 상태다. QA 중단으로 전투·포획·파티/PC·저장 재개·이미지 표시는 미검증이며 지역 호수 사건도 별도 연결해야 한다.

### 종별 조우 레벨 목록 (2026-09-13)
