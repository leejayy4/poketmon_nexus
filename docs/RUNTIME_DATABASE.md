# 공통 데이터 계약 — 설계·실행·플레이 상태

문서 분류: **확정 기준 · 데이터 계약** · 통합 기준일: 2026-09-22.
실행 데이터와 공통 데이터 기준의 고유 계약을 이 문서에 통합했고 중복 사본은 삭제했다.
지역별 추가 로그와 옛 수량은 [과거 통합 기록](archive/README.md)에서 찾는다. 현재 정적 수량·구현 증거·검증 상태는 [PROJECT_STATE](PROJECT_STATE.md)가 소유한다.
확정 서사는 [NEXUS_MAIN_STORY_CANON](story/NEXUS_MAIN_STORY_CANON.md), 기술·저장 이행은 [DEVELOPMENT](DEVELOPMENT.md), 제작 순서는 [STORY_AXIS_ROADMAP](STORY_AXIS_ROADMAP.md)을 따른다.
이번 통합은 문서 작업이다. 생성기·진단 함수·게임 코드·저장을 실행하거나 변경하지 않았으며 QA 중단을 유지한다.

## 1. 세 층과 공통 원칙

| 층 | 실제 위치 | 책임 |
|---|---|---|
| 설계 원본·참고 결과 | 채택 서사, `design-data/nexus-plan.json`, 초안 입력 문서, 생성 설계 DB | 제작 대상·후보 수치·원자료 근거. 생성 DB는 편집 원본과 구분 |
| 실행 정의 | `src/data/*`, `runtime-pokemon-data.json`, 지도·트레이너·이벤트 등록 코드 | 현재 지원 종·기술·진화·조우·아이템·맵·조건 |
| 플레이 상태 | `SaveData`, `Pokemon` | 실제 개체·HP·기술·PP·경험치·가방·배지·플래그·위치 |

종·기술·타입·아이템 효과는 지방 공통이다. 지방 차이는 서식지·입수처·재고·편성·시설·사건에 둔다.
지방 이동으로 파티·박스·도감·돈·기술·배지를 초기화하지 않는다. 방문이나 설계 CH 번호가 곧 개방 조건은 아니다.
원작 사실, 사용자 확정 설정, 프로젝트 재구성, 코드 연결, 직접 플레이 검증을 별개로 기록한다.
논리 테이블 명칭은 SQL 도입이나 별도 테이블 구현 선언이 아니다. 현재 저장소는 TypeScript 객체·JSON·브라우저 저장을 사용한다.
설계 DB 전체를 실행체에 자동 import하지 않는다. 종 파일·이미지·`implementation: runtime`의 존재가 플레이 완료 증거는 아니다.

## 2. 출처·버전·지원 수준

수치 출처는 [설계 출처 명세](design-data/source-manifest.json)와 [실행 출처 명세](../public/assets/pokemon-runtime-sources.json)에 기록한다.
현재 데이터 고정 커밋은 `d4f9a4af58ade123fbc0558f68b1c69daa97d9e4`, 스프라이트 고정 커밋은 `6e523c72bb714306c90912647e0b2ccc4fd2fff1`이다.
이는 출처 식별자이며 모든 행의 공식 검증이나 최신 버전 동기화를 뜻하지 않는다. PokéAPI는 커뮤니티 자료다.
한국어 이름은 공식 도감 대조 기록을 활용하되, 종·기술·수치의 모든 행을 공식 개별 확인했다고 주장하지 않는다.
기본 실행 습득표는 Platinum, 종별 `learnsetOverrides`는 BW2다. 위력·타입·상성은 고정 스냅샷, 전투·성장은 프로젝트 규칙이다.
관장 설계의 여러 세대 습득 후보 합집합과 현재 실행 습득표를 구분한다. BW·BW2풍 시각 목표로 자료 버전을 암묵적으로 바꾸지 않는다.
지리 참고는 `REGIONS`의 신오 Pt·관동/성도 HGSS·하나 BW2를 기본으로 하고 지역별 예외의 버전을 명시한다.
출처에는 버전·장소/층·방법·조건·조회일·URL 또는 원자료 행·프로젝트 조정·제외 범위를 남긴다.
`RUNTIME_ORIGIN`은 혼합 자료, `ITEM_ORIGIN`은 프로젝트 효과·가격임을 표시한다. `verification: not-verified-by-catalog`는 실행 검증을 보장하지 않는다.
자산은 URL·해시·가공·기존 파일 보존을 출처 명세에 남긴다. 파일 존재와 화면 표시·음향 청취를 구분한다.

## 3. 논리 모델과 관계

아래 필드는 자료 작성 시 빠뜨리지 않을 관계다. 실제 JSON에 없는 필드를 이미 지원한다고 보고하지 않는다.

| 논리 대상 | 식별자와 필요한 정보 | 연결·지원 경계 |
|---|---|---|
| 종 | 전국번호, 기본 모습, 이름·타입·종족값·포획률·성장률·전설/환상 구분 | 습득·진화·서식지의 공통 부모. 실행은 선택 종만 추출 |
| 모습·특성 | 종/모습 ID, 타입·능력치 차이, 특성 ID·슬롯 | 기본 모습 참고 중심. 출신 지방과 지역형은 별개이며 전체 폼/특성 효과는 미지원 |
| 기술 | 숫자 ID, 이름·타입·분류·위력·명중·PP·우선도·대상·효과 | 정의와 실제 지원 효과를 분리. 같은 기술을 지방별로 재정의하지 않음 |
| 습득 | 종/모습 + 기술 + 버전 + 방법 + 레벨/도구 | 배울 수 있음과 현재 배운 기술을 분리 |
| 타입·전투 규칙 | 공격/방어 타입, 기준 버전, 배율·효과 규칙 | `typeChart`, `moves.rule`, `battle.ts`가 실제 소비 |
| 진화 | 이전/이후 종·모습, 조건·도구·시간/장소, 출처와 변경 이유 | 교환 대체 등 프로젝트 규칙을 명시. 실행은 추출한 레벨 진화만 |
| 아이템 | `IT-`/`KEY-`/`TM-`, 분류·대상·효과·소모·가격·상한 | 원자료 `referenceCost`와 프로젝트 구매가를 분리 |
| 입수·재고 | 장소/시설 + 종/아이템, 조건·가격·수량·재입수 | 선물·야생·교환·복원·상점을 구분. 후보 경로는 실제 서비스가 아님 |
| 조우 풀·슬롯 | 원본 `ENC-`, 프로젝트 node, MapId, 방법·시간·계절·종·가중치·레벨 | 원작 표와 실행 부분집합을 구분하고 실제 지형에 연결 |
| 장소·교통 | 지방·노드·MapId·층·시설·양끝·경유·출구·도착·수단·조건·귀환 | 거점 간선과 실제 `warps`를 구분. 전체 교통 테이블 구현은 아님 |
| 트레이너·체육관 | 고유 ID·장소·편성·접수·승리·배지·TM·상금·재대전 | 일반 선택전과 본편 관장 분리. 배지 수로 다른 체육관 승리를 추정하지 않음 |
| 사건·활동 | 이벤트 ID·확정 상태·장소·조건·행동·결과·보상·일회성 | 설계 퀘스트와 코드 핸들러·실제 완료 플래그 분리 |
| 소유 개체·도감 | 종·레벨·경험치·HP·기술·PP·만난 곳·파티/박스·색상 | 개체와 종별 발견/포획 기록은 서로 다른 대상 |
| 표현·출처 | 종/모습/맵/효과, 자산 경로·방향·크기·출처·해시·지원 | 실제 렌더러/음향 소비와 검증 결과를 별도로 확인 |

관계의 중심은 `종 → 습득표 ← 기술`, `종 → 진화 → 종`, `장소 → 조우 풀 → 종`, `장소 → 입수처 → 아이템`, `장소 → 연결 구간 → 장소`다.
`Pokemon.nature` 문자열의 존재는 성격 수치 보정을 뜻하지 않는다. 현재 영속 개체 ID·IV/EV·성별·개체 특성 지원과 혼동하지 않는다.
원자료/설계 기술의 `null` 위력·명중은 고정 수치가 없거나 해당 없음이므로 0 피해·0% 명중으로 해석하지 않는다.
현재 익스포터는 실행 `power` 빈값을 0으로 정규화하고 `rule`로 별도 효과를 처리한다. 이 실행 표현을 원자료 값으로 역기록하지 않는다.

## 4. 안정 키와 카탈로그

| 실행 조회 | 키 | 호환 계약 |
|---|---|---|
| `REGIONS` | `sinnoh/kanto/johto/unova` | 표시명에서 지방을 추정하지 않음 |
| `RUNTIME_DATABASE.species` | 숫자 종 ID | 자료·습득 버전·`ownable` 구분 |
| `RUNTIME_DATABASE.moves` | 원자료 숫자 기술 ID | 현재 한국어 기술명 조회와 저장 기술 문자열은 호환 유지 |
| `RUNTIME_DATABASE.pools` | 프로젝트 `node` | `ENC-`는 여러 재구성 풀에서 공유될 수 있어 기본 키로 쓰지 않음 |
| `RUNTIME_DATABASE.evolutions` | `from:to:level` | 현재 레벨 진화 관계만 조회 |
| `ITEMS` | 기존 IT ID | `pokeBalls/potions` 가방 키와 별개로 효과·가격 공유 |
| `WORLD_DATABASE` | 정규화한 MapId | 기존 별칭, 실제 크기·출구·도착점 유지 |
| `ROAD_TRAINER_DATABASE` | `map:event` | 기존 trainer ID·`trainerWon:` 기록 보존 |
| `GYM_DATABASE` | `roark/gardenia/fantina/maylene` | 현재 구현 관장만 조회. 설계 전체를 자동 활성화하지 않음 |
| `SINNOH_DELIVERY_OBJECTIVES` | `observation/research/ferry` | 기존 전달 목표를 읽음. 새 본편 진행 구조와 동일하지 않음 |

카탈로그는 `get/require/has/all`로 조회하고 중복 키를 오류로 처리한다. 누락 종·기술·아이템·맵을 비슷한 이름으로 임의 대체하지 않는다.
목록의 고정은 중첩 객체까지 모두 복제·동결했다는 뜻이 아니다. 플레이 중 정의를 수정하지 않고 가변 상태를 저장 객체에 둔다.
종 ID·MapId·배지·TM·수령 플래그·`met` 출처를 보존한다. 표시명 변경은 별칭과 명시적 이행으로 처리한다.

## 5. 생성 입력·결과·실행 소비

1. `docs/design-data/nexus-plan.json`과 고정 CSV, `docs/개발용_초안맵.md`·`docs/개발용_초안스토리.md`가 현재 설계 생성 입력이다.
2. `scripts/design/build_databases.py`가 입력 표를 파싱하여 설계 JSON·개발용 DB 문서·출처 명세·`validation.json`을 만든다.
3. `scripts/design/export-runtime-pokemon.py`가 설계 종·진화·선택 조우와 `scripts/design/runtime-local-pools.json`, 고정 CSV를 읽는다.
4. 실행 출력은 `src/runtime-pokemon-data.json`이며 출처 결과는 `public/assets/pokemon-runtime-sources.json`이다. `--assets`는 필요한 자산 취득 단계다.
5. `src/data/runtime.ts`가 실행 JSON을 읽고 `pokemon.ts`, `growth.ts`, `battle.ts`, `runtime-encounters.ts` 등에 공통 뷰를 제공한다.

두 초안 문서는 내용의 채택 여부와 별개로 **현재 파서 입력**이다. 경로·표 열·ID 형식을 바꾸려면 파서 이행을 함께 계획한다.
생성기에 남은 기존 필수 체육관 판정과 익스포터의 Lv25 학습/조우 제한은 신정사 대응 전 상태다. 생성 결과가 새 서사를 확정하지 않는다.
수치·팀·배치 변경은 입력과 생성기에서 처리한다. 생성 설명도 렌더러 원본에서 고치며 결과 파일만 손으로 수정하지 않는다.
전체 설계 변경은 설계 생성기, 실제 적용할 범위는 런타임 익스포터 순서로 다룬다. 문서 작업만으로 재생성하거나 다운로드하지 않는다.
지역 풀의 `source` 존재만으로 출처 검증 완료라 하지 않는다. 원자료 버전·제외 종·조건·프로젝트 레벨 조정과 실제 바인딩을 함께 확인한다.

## 6. 조우·생태·획득

실제 조우에는 실행 풀, `runtime-encounters.ts`의 MapId→node 바인딩, 현재 맵의 조우 지형과 `Engine.onFieldStep()` 조건이 모두 필요하다.
현재 시간 정책은 `day-only`다. 풀에 이름이 있어도 밤·계절·낚시·수상·박치기·대회 조우를 지원한다고 안내하지 않는다.
풀별 종·가중치·레벨·방법을 기록하고 작성 비율은 합 100을 기준으로 검토한다. 현행 선택 함수는 양수 가중치 합으로 정규화한다.
슬롯의 선택적 `levelChoices`는 유효한 정수·풀 범위 안 값만 사용한다. 유효 목록이 없으면 풀의 전체 레벨 범위를 사용한다.
야생 생성은 종 선택과 레벨 선택에 각각 난수 1회를 쓰고 서식지 표시는 같은 레벨 목록을 읽는다. 변경 시 난수 계약을 함께 검토한다.
지형·원작 이름이 비슷하다는 이유로 다른 맵의 풀을 복사하지 않는다. 숲·습지·동굴의 실제 생태와 지원 부분집합을 명시한다.
생활 NPC·전시 포켓몬·진정전 상대는 일반 야생 슬롯이 아니다. 포획 가능한 개체와 설명용 배치를 구분한다.
상록숲 피카츄 야생 출처와 연구소 선물은 별개다. 반복 포획과 일회 선물 제한을 섞지 않고 `grantPokemon()`을 일반 선물 API로 재사용하지 않는다.

## 7. 학습·진화·아이템

`availableMoves()`는 레벨 학습·현재 기술·보유 TM과 종별 습득 근거를 함께 읽는다. 선택 기술은 `Pokemon.moves`, 습득 후보는 종 자료다.
현재 최대 네 기술이며 옛 기본 두 칸 저장을 읽는다. 슬롯 추가·교체에는 확인과 저장·PP 초기화를 함께 적용한다.
이전 진화 단계의 기술은 `levelMoves()`가 추적하며 방문 집합으로 순환을 막는다. 진화가 기존에 합법적으로 배운 기술을 무효화하면 안 된다.
진화는 실행 추출 목록과 조건을 모두 만족해야 한다. 설계에 있는 도구·교환·친밀도·장소 진화를 다른 방법으로 임의 대체하지 않는다.
현재 상한 호환 규칙은 승리 참여·생존·이미 Lv25인 개체의 허용 레벨 진화를 한 단계 처리한다. 불러오기·도주·패배 때 자동 진화하지 않는다.
해당 보상에서 새로 상한에 도달한 개체를 같은 규칙으로 다시 진화시키지 않는다. 장기 성장 전환은 저장 이행과 함께 설계한다.
`RUNTIME_RULES`의 레벨·파티·박스·기술·가방·구매 상한은 현재 실행 계약이다. 장편 목표 수치로 문서만 바꾸지 않는다.
`ITEMS`의 몬스터볼과 상처약을 상점·가방·전투가 공유한다. 현행 순서·가방 키·가격·효과를 지역마다 복제하지 않는다.
상처약은 20HP 회복이며 부활하지 않는다. 몬스터볼은 상대 HP 절반 이하에서 성공, 그 외 55%인 프로젝트 규칙으로 원작 포획식이 아니다.
아이템 정의, 판매·획득 조건, 현재 재고 수량은 분리한다. 판매·복원·소지품·중요품 효과는 자료가 있다는 이유만으로 활성화하지 않는다.

## 8. 전투 지원과 PP

현행 피해 계산은 종족값의 공격/방어 또는 특수공격/특수방어, 레벨·위력·자속·타입 상성을 읽는다. 물리 랭크와 고정/레벨/무게 피해는 해당 `rule`을 따른다.
속도는 종족값과 레벨로 계산하고 기술 우선도→속도→동률 난수 순서로 기술 행동을 결정한다. 상대 기술은 한 턴에 한 번 선택한다.
앞선 행동에서 기절·종료·교체가 발생하면 남은 기술을 실행하지 않는다. 교대·도구·도주의 별도 처리를 전체 행동 큐 구현으로 표현하지 않는다.
IV/EV는 0, 성격 배율은 1로 계산하며 기존 HP 성장과 랭크 상한을 사용한다. 원작 모든 세대의 전투 재현이 아니다.
명중률·급소·피해 난수·주요 상태이상·특성·소지품 효과는 현재 미지원이다. 독침의 직접 피해를 독 부여 구현으로 안내하지 않는다.
피해 예측·플레이어 공격·상대 AI는 공통 계산을 읽고 대사·HP 표현은 `TurnResult.frames`를 사용한다.

- PP 단일 출처는 고정 `moves.csv`의 `pp` 열이다. 지역·관장 모듈에서 기술 PP를 다시 정의하지 않는다.
- `src/move-pp.ts`의 조회·사용 가능·소모·회복·슬롯 초기화·검증 API를 사용한다. `Pokemon.pp`는 현재 기술 순서의 선택적 배열이다.
- 옛 저장의 누락/짧은 PP 배열과 기술 상한을 넘는 잔존 카운터는 읽을 때 해당 기술 전량으로 해석한다. 저장 검증은 형식·로스터 상한을 별도로 본다.
- 플레이어 기술이 실제 실행될 때 소모한다. 행동 전에 쓰러지거나 선택이 거부되면 소모하지 않는다. 교체/새 학습 기술은 해당 슬롯 전량으로 시작한다.
- 소진 기술은 다른 사용 가능 기술이 있으면 턴 소비 없이 거부한다. 모든 기술이 소진되면 발버둥으로 처리하며 발버둥은 PP 카운터가 없다.
- 센터와 전체 회복 지점은 HP·PP를 복구하고 필드 상처약은 HP만 회복한다. `pallet-sparring` 연습전은 사본의 양쪽을 전량 회복한다.
- 상대 PP 제한·PP 강화·포인트업/포인트맥스·에테르류는 미도입이다. PP 구현이 전체 자원·도구 체계의 완성을 뜻하지 않는다.

## 9. 특별 개체 전투와 코드 이벤트

`createSpecialBattle(save, {eventId, species, level, met, allowCapture, shiny?})`는 일반 조우표와 독립적으로 상대를 만든다.
건강한 활성 동료, 지원 종·레벨·소유 가능 계약을 확인한다. 사건 조건·중복 획득·재도전 관리는 호출하는 지역 이벤트가 맡는다.
진정전과 선택 포획은 서로 다른 eventId를 사용한다. 포획 금지 전투의 볼 선택은 소비 전에 거절한다.
실제 종료에서 `specialBattle:<id>:won/caught/escaped/lost`를 기록하고 `specialBattle:<id>:last`는 각각 1/2/3/4로 저장한다.
패배 결과는 회복 전 기록한다. 도주·패배·전투 중 저장·복귀는 진정 또는 포획 완료가 아니다. API가 본편 장 플래그를 자동 지급하지 않는다.
`Pokemon.shiny?:boolean`은 없으면 일반 개체다. 현재 특별전투의 붉은 변형과 양면 자산 지원은 종130으로 제한된다.
색상은 개체 복사·포획·스냅샷에서 유지한다. 종130의 소유 허용은 일반 조우나 잉어킹 진화 구현을 뜻하지 않는다.

`StoryCondition`의 `flag/badge/all/any/not`와 `meetsStoryCondition()`은 읽기 전용이다. 숫자/불리언 플래그의 기존 참/거짓 해석을 유지한다.
현재 선언형 목표 연결과 새 정사의 전체 사건 그래프를 구분한다. `CH/SQ/PG/LEG` 레코드는 코드 핸들러나 플레이 완료 증거가 아니다.
실제 사건은 채택 서사의 행동·결과를 코드 이벤트에 연결하고 취소·패배·재진입·한 번만 지급하는 보상을 함께 처리한다.
범용 퀘스트 저장·보상 트랜잭션·전 지역 자동 등록은 이미 구현된 것으로 보지 않는다. 데이터 조회가 플레이 상태를 변경해서는 안 된다.

## 10. 적용과 검증의 경계

새 자료는 해당 여정에 필요한 종·기술·입수처부터 원본→생성→바인딩→행동→표현→저장 순으로 연결한다. 미지원 조건은 명시적으로 제외한다.
`WORLD_DATABASE`는 조립된 맵을 지연 조회한다. `getMap()`의 수거물·장애물·통행·NPC 상태는 매번 현재 저장에서 투영하고 카탈로그에 캐시하지 않는다.
`inspectRuntimeReferences()`는 명시 호출용 제작 진단이다. 종 기술·진화 양끝·조우 종/소유·범위·가중치를 확인하며 시작·import 시 자동 실행하지 않는다.
설계 `validation.json`과 위 진단은 지도 출구·서사·보상·저장·플레이·밸런스·화면·음향 검증을 대신하지 않는다.
QA 재개 후 변경 범위의 참조·슬롯·진화·도구 소비·중복 보상·이행을 검사하고 [콘텐츠 제작 기준](MAP_STORY_DESIGN.md)에 따라 실제 여정을 확인한다.
QA 중단 동안은 코드 연결·정적 확인과 미검증을 구분해 [PROJECT_STATE](PROJECT_STATE.md)에 기록한다. 옛 통과 수치와 생성 성공을 새 완료 판정으로 사용하지 않는다.
