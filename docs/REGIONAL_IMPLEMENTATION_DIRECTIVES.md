# 외부 참고 자료의 지방별 적용 지시

## 0. 외부 자료를 사용하는 방법

### 0.1. 세계관·맵·스토리 참고 사이트

네 지방 담당자는 현재 도시·도로·동굴을 구현할 때 아래 자료를 목적에 맞게 사용한다. 우선순위는 조사 순서이며 자료 간 충돌을 순위만으로 결정하지 않는다.

| 우선순위 | 사이트 | 가장 유용한 용도 | 주의점 |
| ------------------- | ---------------------- | ------------------------------------- | ---------------------------------------------------------- |
| 1                   | Bulbapedia             | 세계관, 도시·도로 연결 관계, 버전별 차이, 등장인물, 사건 순서 | 영어 자료이며 게임 버전별 내용을 구분한다.                                   |

지방별 기본 대조 버전은 신오 Pt, 관동·성도 HGSS, 하나 BW2다. 

각 도시의 적용 기록에는 **정확한 참고 페이지 URL·확인일·게임 버전·원작 사실·프로젝트 변경·적용 MapId/이벤트·구현 및 검증 상태**를 남긴다. 조사 출처는 [REFERENCE\_RESEARCH](REFERENCE_RESEARCH.md), 실제 연결은 [WORLD\_ROUTES](WORLD_ROUTES.md), 사건 적용은 [MAP\_STORY\_DESIGN](MAP_STORY_DESIGN.md)과 연결한다. 참고 목록에 있다는 이유만으로 해당 내용을 조사·구현·검증 완료로 표시하지 않는다.

**문서 역할:** 루트 AGENTS가 지정한 지방별 구현의 필수 우선 기준이다. 작업 선택·도시 산출물·외부 자료의 실제 적용을 담당한다. 운영/QA는 AGENTS, 서사·지리·크기·데이터는 [문서 책임표](README.md)의 담당 기준을 따른다. 날짜별 반영 기록은 현재 품질의 보증이나 새 작업 배정으로 사용하지 않는다.

> 후속 코드 반영: [네 지방 기존 장소 후속 구현](autonomy/regional-continuation-20260913.md). 211 선택 산길, 쌍둥이섬 층별 곁길/조사 접근, 무궁 동료 상태 반응, 설화습지 기록/길안내를 적용했다. 상점 등록·실제 시설 안내·생활 포켓몬 개별 표시도 수정했으며 QA는 미실행이다.

> **2026-09-13 우선 작업: 기존 장소 품질 회복.** 사용자가 빈 들판·이상한 맵 구현을 지적했다. 이번에는 새 지도와 크기 확대보다 이미 연결한 장소의 지형·생활 동선·보이는 출입구·현지 포켓몬·활동을 보수한다. 적용 내용은 [기존 맵 보수 기록](autonomy/regional-map-repair-20260913.md)을 따른다. 현재 QA는 중단이며 2026-09-12 재개/후속 지시는 과거 이력이다.

2026-09-12 제정, 2026-09-13 보수 우선순위 갱신. 이 문서는 참고 내용을 구현 작업으로 연결한다. 서사 확정은 NEXUS_STORY_MASTER, 실제 진행은 STORY, 출구는 WORLD_ROUTES, 크기는 MAP_SIZE_STANDARDS, 실행 데이터는 RUNTIME_DATABASE를 따른다. QA 정책은 루트 AGENTS와 최신 사용자 지시를 따른다.

### 기존 맵 보수의 필수 조건

- 충돌 격자에만 있는 벽·절벽을 빈 바닥처럼 그리지 않는다. 물·꽃밭·건물을 보행 칸 위에 겹쳐 칠하지 않고 실제 출입구를 남긴다.
- 조우 구역은 특정 도시 이름 목록이 아니라 실제 맵의 조우 지형 데이터에서 그린다. 동굴 조우는 야외 풀밭과 구분한다.
- 전용 그림과 실제 도로가 있는 도시에 공통 십자형 길을 덧붙이지 않는다. 도시 고유 배치를 작은 색상 변화로 대체하지 않는다.
- 새 painter는 실행 렌더러 호출까지 연결한다. 조사물은 그림·충돌·대사 데이터가 같은 위치/이벤트를 가리키게 한다. 개발 지도 좌표도 함께 등록한다.
- 확장 전 담당 도시의 랜드마크·필수 실내·진입/출발·현지 동료·행동 결과를 채운다. QA 중단 중의 구현 결과는 **보수 코드 반영·미검증**으로 남기며 원작 재현·도시 완료로 표시하지 않는다.

## 1. 이번 비교의 정정

현 작업 트리 조회: 활성 맵568개, 등록57종, 소유50종, 조우31풀, 기술53개, 진화5개. 코드 조회 스냅샷이며 플레이 완성도 수치가 아니다. 레벨 상한은25이며 지도 추가만으로 성장 상한을 바꾸지 않는다. 공통 카탈로그는 이미 연결됐다. 종 데이터에 공격·방어·특수·속도, 기술 데이터에 우선도가 있다고 전투 계산까지 지원하는 것은 아니다. battle.ts는 2026-09-13 종별 능력치·물리/특수·자속 계산을 연결했다. QA 미실행이며 세부 제한은 RUNTIME_DATABASE 최신 전투 절을 따른다. PP·명중·상태·특성·소지품은 개별 실행/저장/회복 지원을 확인한 뒤 구현 상태를 기록한다.

현재 목표는 BW·BW2풍이다. pokeplatinum은 플라티나 지리·기존 DS 구현을 참고하는 자료이며 BW2 그래픽 사양서가 아니다. stars는 과거 조사 시점의 인기 참고값으로만 보존하고 기능 채택 순위를 정하는 기준으로 삼지 않는다.

## 3. 도시 하나의 필수 작성·구현 항목
 
### 외부 자료 적용 기록의 작성 절차

2절의 사이트/프로젝트 목록을 다시 붙이는 것으로 조사를 대신하지 않는다. 현재 도시의 변경에 필요한 개별 페이지 또는 파일을 읽고 아래 양식으로 REFERENCE_RESEARCH에 기록한다. 기존 유효한 조사 기록은 링크로 재사용하고, 버전이나 적용 범위가 달라진 부분만 다시 확인한다.

| 항목 | 기록할 내용 |
| --- | --- |
| 대상 | 지방·도시·도로/동굴·MapId·이벤트 ID |
| 출처 | 해당 장소의 정확한 URL, 확인일, 게임 버전; 소스는 파일 경로와 commit/tag |
| 확인 사실 | 실제 읽은 본문/지도/데이터가 뒷받침하는 지형·출입구·종·사건 |
| 현재 차이 | 해당 코드 경로와 원작과의 구체적인 차이 |
| 적용 결정 | 원작 반영 / 넥서스 재구성 / 미채택 및 이유 |
| 실제 연결 | 수정 파일과 생성·이벤트·렌더러 소비 위치; 미연결이면 명시 |
| 관련 기준 | WORLD_ROUTES의 경유, MAP_STORY_DESIGN의 사건 기록 링크 |
| 상태 | 자료 확인 / 설계만 / 코드 반영 / 플레이 검증을 각각 구분 |
| 재사용 | 코드·자산 재사용 여부; 재사용했다면 원본 파일·버전·라이선스 |

접근 실패·미열람 자료는 미확인으로 남기며 검색 요약이나 사이트 이름으로 확인일을 채우지 않는다. 기존 연결 오류 보수는 원작 조사 없이도 진행할 수 있으나 ‘프로젝트 오류 수정’으로 기록하고 원작 대조 완료로 올리지 않는다. QA 중단 중에는 자료 읽기와 구현을 계속하되 플레이 검증란은 미실행으로 둔다. 이 기록은 새 승인 절차나 도시마다 모든 사이트를 읽으라는 요구가 아니다.

1. 방문 목적: 넥서스 본편 장/퀘스트 ID와 연결하거나 선택 생활 활동임을 명시한다. 후자의 기록을 본편 완료로 대체하지 않는다.
2. 여행: 직전 거점→공식 도로/동굴→현재 도시→다음 경유를 MapId, 출구 좌표/방향, 도착 좌표, 귀환 조건과 함께 작성한다. 화면 그림·보행·미니맵·개발 지도·저장 이행의 등록 누락을 확인한다.
3. 동료: 실제 조우표의 종·레벨·서식 이유, 포획 공급, 회복 지점을 정한다. 포획하지 않아도 본선이 열려 있어야 하는 활동은 그대로 유지한다.
4. 행동: 선택 전투·훈련·동료 활용을 사건 해결과 연결한다. 관찰 문장 하나를 읽는 것만으로 완료하지 않는다. 구현되지 않은 기술 효과나 보상을 가정하지 않는다.
5. 결과: 전/중/후 플래그, 대화와 환경 변화, 보상 중복 방지, 취소·패배·재방문 상태를 적는다. 새 보상은 승인된 퀘스트/경제 계약을 따른다.
6. 공간 밀도: 화면3~5개를 통과하는 구간마다 달라지는 랜드마크·길 폭·지형·만남/발견·휴식·출구 예고를 표시한다. 모든 칸에 이벤트를 넣거나 맵을 정사각형으로 강제하지 않는다.
7. 완료 근거: 해당 도시의 정상 진입→활동→다음 출구→귀환→저장 재접속. 준비 저장·자동 검사·자연 진행·시각/음향 근거를 구분한다.

## 5. 공통 시스템 후속 순서

실행 불가·진행 막힘·저장 손상 해결이 먼저다. 그 뒤 종별 실전 능력치/물리·특수→속도·우선도→PP·명중→상태이상→특성·소지품 순으로 기존 지원을 확인하며 적용한다. 각 단계에 저장 기본값/이행, UI 설명, 센터 회복, 트레이너/야생 판정, 난수 고정 회귀를 함께 정의한다. 외부 목록의 기능 이름만 추가하지 않는다.
