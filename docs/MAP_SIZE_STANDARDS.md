# 맵 크기 기준과 전체 대장

2026-09-12 부분 적용: 갈색 외부72×56, 센터28×22, 상점24×20, 터미널 3개 층 각각28×24, 공동주택 6개 층 각각24×18 목표를 코드에 적용했다. 홍련–갈색/갈색–블루 창작 해안길도 각각72×36으로 확대했다. 동쪽 운하 일반 출구(70,12)·귀환(69,12), 하역 수면/남쪽 산책 데크와 기존 시설 문을 함께 유지한다. 사용자 지시에 따라 모든 QA가 일시 중단되어 현재 수치는 **코드 반영값이며 실행 확인값이 아니다**. 실제 도시 횡단 보행 길이는 활동 배치와 QA 재개 후 측정한다. 신규 던전층은 이번 범위에 없다. 아래 최초 조회/문서만 적용이라는 설명은 이 갱신을 제외한 이력이다.

2026-09-10 사용자 크기표를 조금 넓힌 **프로젝트 설계 목표**다. 단위는 **가로×세로 타일**이며, 바깥 벽·물·절벽·건물 면적을 포함한 맵 사각형이다. 원작의 정확한 타일 수를 추출한 결과가 아니다. 현재 크기는 실행 맵 조회값, 목표 크기는 앞으로 적용할 설계값으로 구분한다. 문서만 수정했으며 맵 확대는 미적용이다.

**형태 원칙: 모든 맵을 정사각형으로 맞추지 않는다.** 도시의 가로/세로 거리, 해안선, 활주로, 도로 진행 방향, 동굴의 방과 통로를 먼저 배치하고 사각형 경계를 정한다. 표의 범위는 규모를 고르는 기준이며 정사각형 강제나 가로·세로 비율의 하한 규칙이 아니다. 지형상 필요하면 범위의 두 축을 바꾸거나 면적과 배치 근거를 기록해 비율을 조정한다.

“조금 크게”는 사용자 표 대비 각 변의 소폭 증가다. 현재 축약된20×18 숲 등을 새 기준으로 확대하면 기존 구현 대비 증가는 클 수 있다. 표 범위의 양끝은 각각 작은/큰 장소의 기준이며 모든 맵을 상한으로 만들지 않는다. 가로형 도로는 두 축을 바꿔 쓴다. 굽은 길은 바깥 사각형과 실제 이동 길이를 따로 기록한다.

기존 새잎마을은40×30이므로 가로를 줄이지 않는 **40×36 예외**를 둔다. 체육관32×28·박물관/방송/터미널28×24는 별도 활동 실내 기준이다. 폭이 넓은 항만 도시는64×56처럼 직사각형을 쓸 수 있다. 원작 시설을 참조한 박물관/탑 전시실과 실제 던전층은 같은 크기 규칙으로 취급하지 않는다.

### 에메랄드 데이터의 비율 참고

[pret/pokeemerald의 layouts.json](https://github.com/pret/pokeemerald/blob/master/data/layouts/layouts.json)을 2026-09-10 조회했다. 이는 커뮤니티의 게임 재구성 저장소이며 공식 개발문서는 아니다. 해당 데이터의 width/height는 LittlerootTown(미로마을)20×20, RustboroCity(잿빛도시)40×60, MauvilleCity(보라시티)40×20, LilycoveCity80×40, EverGrandeCity40×80이다. 사용자가 제시한30×30·50×70은 이번에 조회한 파일의 앞 두 값과 다르므로 원본 실측값으로 기재하지 않는다. 별도 확장안과 원본 데이터 수치를 구분한다.

이 자료는 장소별 종횡비가 다르다는 근거로 사용한다. GBA 레이아웃의 셀 수를 DS 그래픽 프로젝트의 화면 픽셀이나 이동 거리로 그대로 환산하지 않는다. 호연지방을 게임 구현 범위에 추가하는 것도 아니다.

## 3. 공간을 사용하는 규칙

- 도시 큰길은 보통4~6칸, 골목은2~3칸을 배정하고 문 앞·안내원·동료의 통행 공간을 겹치지 않게 한다. 이는 설계 기준이지 현재 충돌 타일 규칙이 아니다.
- 실내는 문→주요 기능→계단/귀환이 읽히게 만든다. 작은 방을 넓힌 만큼 빈 바닥만 늘리지 않고 가구 사이 이동과 동료 반응 공간으로 사용한다.
- 도로는 진입→지형 변화→선택 관찰/도전→재합류→도착을 배치한다. 긴 길은2~3개의 풍경 단락과 안전한 준비/휴식 지점을 둔다. 모든 여백을 풀밭이나 트레이너로 채우지 않는다.
- 층마다 입구/출구·계단·퍼즐·귀환을 기록한다. 신규 층수는 아래 프로젝트 분할안이며 원작 층수의 정확한 복제가 아니다. 미채택 선택층은 필수 통과 조건이 아니다.
- 적용 때 맵별 `현재 크기 / 목표 크기 / 실제 보행 길이 / 출구 좌표 / 활동 / 이행 상태`를 갱신한다. 크기 확정이 기존 좌표의 비례 확대를 뜻하지 않는다.
- 현재 도시 QA를 중단해 전 지방을 일괄 확대하지 않는다. 다음 도시 설계/개편에 적용하고 같은 도시의 진입·실내·스토리·출발 구현을 마친 뒤 QA한다. 저장·met·방문 기록 보존은 [상세 규칙](AGENTS.md)을 따른다.
- 크기의 단일 기준은 이 문서다. 다른 문서의 “현재32×20”은 실측 이력이고, 이전 “48×34~54×38 후보” 등 목표값은 이 문서로 대체한다. 신규 목표 변경 시 여기와 맵별 이야기 요구를 함께 갱신한다.

## 4. 현재 등록 맵 전체의 현재·목표 크기

코드의 `ACTIVE_MAPS`402개를 조회했다. 등록되지 않은 옛 별칭은 중복 집계하지 않는다. **현재 수치는 조회 확인 / 목표 수치는 설계 지정·구현 미적용**이다. 표의 기존 장소명은 현재 코드의 이름이며 공식 지명 이행은 [WORLD_ROUTES](WORLD_ROUTES.md)를 따른다.

이 대장의 기존 통로 목표는 호환 구간의 공간 계획이다. 공식 도로·동굴로 분할할 때는 제5절의 개별 맵 크기가 우선하며 옛 직통로와 새 본선을 모두 필수로 구현하라는 뜻이 아니다. 기존 전시시설의 층별 목표는 공통 활동 실내 기준을 배정한 것이며, 각 층의 상세 가구·장면 설계 완료를 뜻하지 않는다.

## 6. 적용과 검증 범위

이 문서는 현재402개 MapId의 크기 누락을 해소하고, 신규 경유지와 던전에 구체적인 목표 또는 층당 예산을 배정한다. “층당”으로 적은 후반 후보는 전체 층수·전체 면적까지 확정한 것이 아니다. 채택되지 않은 장기 초안 전체를 구현 대상으로 추가하지 않는다.

도시 착수 때 해당 도시와 진입/출발 맵의 목표값을 설계 배치에 적용한다. 큰길·필수 시설·스토리 행동이 확보됐는지 확인한 뒤 빈 여백을 조정한다. 현재 도시 구현/QA와 실제 저장을 보존하며 코드·자산·게임 저장은 이번 문서 작업에서 변경하지 않는다. 문서 대장과 링크만 확인하고 게임 QA는 도시 구현 완료 뒤 수행한다.
