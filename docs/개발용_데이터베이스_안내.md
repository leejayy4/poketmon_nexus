## 2. 원작 자료와 프로젝트 제안의 경계

한국어 도감 표기·모습 개념은 [포켓몬코리아 공식 도감](https://www.pokemonkorea.co.kr/pokedex)을 우선 참고했다. 따라큐는 [공식 개별 도감](https://pokemonkorea.co.kr/pokedex/view/987)의 고스트·페어리 기본 종으로 대조했다. 분류·수치·진화·조우를 대량으로 연결하기 위해 [PokéAPI 프로젝트](https://github.com/PokeAPI/pokeapi)의 공개 자료를 사용했다. PokéAPI는 포켓몬 공식 배급사의 데이터베이스가 아닌 커뮤니티 프로젝트다. 모든 원자료 행의 공식 검증을 완료했다는 주장은 하지 않는다.

원자료 커밋은 `d4f9a4af58ade123fbc0558f68b1c69daa97d9e4`, 커밋 일시는 2026-09-03T19:01:48Z다. 조회 기준일은 2026-09-06이다. 파일별 SHA-256과 크기는 [출처 명세](design-data/source-manifest.json)에 기록했다. 프로그램은 동일 커밋 파일을 로컬 캐시에 보관해 반복 다운로드를 피한다. [PokéAPI 문서](https://pokeapi.co/docs/v2)의 읽기·캐시 원칙을 참고했다.

| 필드 | 근거 / 결정 수준 |
| --- | --- |
| 전국번호·기본 종 이름·타입·종족값·특성 | 고정 원자료 스냅샷. 공식 이름 일부 대조, 전체 행 공식 개별 검증은 아님 |

| 진화 규칙 | 8세대까지 기본 모습 자료 참고. 교환 대체·이브이 탐험 등 프로젝트 변경을 별도 표시 |

| 아이템 가격·효과 선택·개방 | 프로젝트 규칙. 원작 모든 세대와 동일하다고 주장하지 않음 |
| 현재 구현 | 실사용 지도 391개, 초반 조우 풀 5개·소유 가능 26종·스타팅 첫 진화·기술 2칸 선택·기존 네 TM 사용·상점·박스·도감. 전체 DB 및 모든 기술 효과의 구현은 아님 |

## 3. 데이터 파일과 수정 순서

편집 입력은 [nexus-plan.json](design-data/nexus-plan.json)이다. 원작 사실을 바꾸지 않고 배치·팀·가격 등을 수정한다. 생성 결과는 [pokemon.json](design-data/pokemon.json), [encounters.json](design-data/encounters.json), [evolutions.json](design-data/evolutions.json), [gyms.json](design-data/gyms.json), [items.json](design-data/items.json), [moves.json](design-data/moves.json), [quests.json](design-data/quests.json)이다. 이 JSON 전체를 게임이 직접 로드하지 않는다. 아래 런타임 추출기가 선택한 부분을 별도 JSON으로 내보내고 게임은 그 결과를 읽는다. 세부 출현·진화·보상 수치는 이번 DB를 우선하고, 큰 장 순서·지역 이동·기존 구현 계약은 앞선 스토리·맵·기준 문서를 유지한다.

```powershell
python -X utf8 scripts/design/build_databases.py
```

생성기는 [이전 맵](개발용_초안맵.md)의 90노드·32체육관·123종 표도 읽는다. 기존 표의 열 구조를 바꾸면 파서와 검사도 함께 고쳐야 한다. 문서를 직접 고치기보다 입력 JSON 또는 생성기의 해당 설명을 고친 뒤 재생성한다. 참고 커밋을 바꾸려면 원자료 변경 영향과 이름·조건 차이를 검토한다.

## 4. ID와 참조 계약

전국번호는 원작 species ID, 장소는 기존 S/K/J/U/X, 체육관은 GS/GK/GJ/GU를 유지한다. `ENC-`는 야생 풀, `EV-이전-이후`는 진화, `IT-`는 원작 아이템 기반, `KEY-`는 중요한 물건, `TM-기술명`은 프로젝트 기술머신이며 원작 버전별 TM 번호와 혼동하지 않는다. `MV-` 뒤 숫자는 원자료 기술 ID, `BADGE-체육관ID`는 프로젝트 배지다.

기존 종 ID·MapId·수령 플래그를 보존한다. 현재 저장은 version 1 / worldRevision 23이며 Lv.25까지의 성장, 첫 스타팅 진화, 파티 6마리·박스 60마리, 도감·선택 기술을 검증한다. 스타팅이 진화하거나 박스에 있어도 선물 수령 계보를 검사한다. 누락된 박스·도감 필드는 이전 저장에서 이행한다. 게임의 기존 `grantPokemon()`을 모든 선물에 그대로 재사용하면 일반 스타팅 제한과 충돌한다.

## 5. 검사와 미완성 범위

생성 시 요청123종 누락, 종·진화 부모·필요 도구·체육관 팀·기술 습득 근거·퀘스트 보상·장소 참조·풀 가중치·문서 링크를 검사한다. [validation.json](design-data/validation.json)에 이번 생성 결과를 남긴다. 수록 후보의 자료 검증이며 실제 게임 밸런스·브라우저 플레이 통과가 아니다.

등록 종 33종 중 소유 가능 종은 26종, 선택 야생 풀에 포함된 종은 19종이다. 현재 추출 대상 밖의 레벨업 기술표·모든 원작 기술 효과·32관장의 AI·사천왕 세부 팀·모든 폼·전체 지도 보물 배치는 아직 별도 제작 대상이다. 첫 도로의 작은 종 집합부터 구현하고 각 체육관 단위로 확장한다. 이름만 있는 기술이나 파일만 있는 포켓몬을 플레이 가능으로 표시하지 않는다.


## 6. 실제 게임용 추출과 지원 범위

```powershell
python -X utf8 scripts/design/export-runtime-pokemon.py
# 신규 PNG까지 준비할 때
python -X utf8 scripts/design/export-runtime-pokemon.py --assets
```

입력은 설계 `encounters.json`, `pokemon.json`, `evolutions.json`과 같은 고정 PokéAPI 커밋의 CSV다. 출력은 [runtime-pokemon-data.json](../src/runtime-pokemon-data.json), 출처·해시는 [pokemon-runtime-sources.json](../public/assets/pokemon-runtime-sources.json)에 둔다. 원본 설계 파일의 `implemented` 표기나 전부를 일괄 런타임 완료로 바꾸지 않는다. 배치 변경은 `nexus-plan.json` → 전체 설계 생성 → 런타임 추출 순서로 재생성한다.

| 선택 설계 풀 | 실제 연결 | 조건 |
| --- | --- | --- |
| S02 / ENC-001 | `route_s01` 서쪽길 | 설계 가중치·Lv.3~6 |
| S03 / ENC-002 | `tour_jubilife` 남서 외곽 풀밭 | 설계 가중치·Lv.4~7 |
| S04 / ENC-003 | `tour_pass_jubilife_oreburgh` 암반굴 | 설계 가중치·Lv.7~10 |
| S05 / ENC-004 | `tour_eterna_forest` | 낮 풀·Lv.10~14, 밤 풀 미사용 |
| S15 / ENC-016 | `tour_coronet` 천관산 하부 | 육상·Lv.13~17, 낚시 풀 미사용 |

어느 풀도 CH 조건을 새 본편 잠금으로 바꾸지 않는다. 등록되지 않은 다른 연결길에는 임의 대체 풀을 넣지 않는다. 첫 진화는 설계의 이상해씨→이상해풀·파이리→리자드·꼬부기→어니부기 Lv.16만 적용한다.

기술은 플라티나(version group 9)의 레벨업·TM 호환성을 참고하고, 위력·타입·무게·상성은 고정 자료 스냅샷 값을 쓴다. 모두 같은 원작 세대의 전투 재현이라고 주장하지 않는다. 런타임에는 52개 기술 이름과 제한된 규칙이 등록되며 선택 슬롯은 두 개다. 레벨업 후보와 보유한 기존 네 관장 TM을 **정보 → 기술 배우기**에서 교체한다. TM 보유 기록은 유지한다. 양쪽 직접 피해·반감·무효, 방어, 흡수, 무게 위력, 교대 바위 피해 등은 지원하지만 PP·선공·명중률·급소·확률성 부가효과와 모든 원작 기술 효과는 미구현이다.

상점 가격은 설계 `IT-poke-ball`·`IT-potion`의 200원을 사용한다. 첫 배지 전 무료 보급 이후에는 상점 구매를 안내한다. 주민 활동 두 개와 일반 트레이너 두 명은 별도 코드의 작은 선택 콘텐츠이며 설계 퀘스트 전체의 구현으로 세지 않는다. 외부 개발 UI 개편(#10)·전체 캠페인 수용 작업(#11)은 이번 요청에서 제외됐고, 검증 결과 수량과 실제 화면 증거는 총괄의 [JOURNEY_IMPLEMENTATION.md](JOURNEY_IMPLEMENTATION.md)에서 관리한다.
