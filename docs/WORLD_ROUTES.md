### 원작 재현 수준

- 목표는 1:1 타일 복제가 아니라 **공식 지리·이동 순서·장소 정체성을 보존한 축약**이다.
- 한 도시 사이에 공식 도로가 3~4개 있어도 각각을 대형 맵으로 만들 필요는 없다. 다만 번호가 바뀌는 지점, 고유 랜드마크, 이동 수단이 바뀌는 지점은 맵을 나눈다.
- 화면 표시명은 원작 명칭을 우선한다. 창작 구간은 번호를 붙이지 않고 `서부 연구 연결길`, `공동조사선 선착장`처럼 고유명으로 구분한다.
- 기존 저장 호환을 위해 MapId는 유지할 수 있다. 표시명·월드맵 라벨·서식지 조회에 이행 별칭을 사용하되 기존 포켓몬의 실제 `met` 출처 문자열은 보존한다.

## 1. 표를 읽는 기준

### 번호와 MapId의 단일 기준

원작 번호와 프로젝트 내부 ID를 분리한다. 네 지방의 번호를 억지로 하나의 연속 체계로 만들지 않되, 플레이어가 보는 표지·월드맵·도감에는 각 지방의 공식 번호를 사용한다.

| 지방 | 플레이어 표시 기준 | 내부 관리 기준 | 기존 프로젝트 번호 처리 |
| --- | --- | --- | --- |
| 신오 | 201~230번도로·수로, 천관산·험한샛길 등 공식 고유명 | `S-Rxx`, `S-Cxx` 또는 기존 MapId | 프로젝트 1~12번은 신규 표시에 사용하지 않고 이행용 별칭으로만 보존 |
| 관동 | 1~25번도로·수로. 성도 기반 게임의 26~28번은 공동 접경 구간 | `K-Rxx`, `K-Cxx` 또는 기존 MapId | `관동 9번도로=태초–홍련` 같은 재번호는 폐기하고 공식 21번수로 또는 창작 고유명으로 수정 |

예: `tour_pass_driftveil_mistralton`이라는 MapId는 호환 때문에 유지할 수 있지만, 화면에는 `하나 6번도로`로 표시하고 다음 맵을 `전기돌동굴`로 분리한다. 여러 공식 구간을 한 맵으로 압축하면 `209·210번도로 연결구간`처럼 표기하고, 존재하지 않는 새 번호를 만들지 않는다.

이 문서는 **현재 게임에서 어디를 지나가는지**와 **원작에서 그 도시에 어떤 도로·동굴로 접근하는지**를 나란히 기록한다. ‘현재’의 프로젝트 번호는 기존 코드 설명이고, 이후 구현은 위 표시 기준을 따른다.

- 현재 장소 설명은 [explore-world.ts](../src/explore-world.ts)의 `PLACES`, 통로는 [journey-world.ts](../src/journey-world.ts)의 `PASSAGES`, 최종 경로는 [maps.ts](../src/maps.ts)의 `ACTIVE_MAPS`와 [unified-world.ts](../src/unified-world.ts)로 대조했다.
- 주요 장소 43곳(신오12·관동11·성도10·하나10), 거점 연결 49개(지방 내부45·지방 간4), 기존 공통 생성 통로33개와 추가 접근로4개(PASSAGES 총37)를 아래 연결별로 설명한다. 시작 새잎마을·서쪽길·연구 연결길은 별도 설명한다. 실내·층·옛 저장 별칭은 주요 도시 수에 중복 집계하지 않는다.
- ‘장소’는 마을·도시·숲·산·호수·탑 등 방문 거점, ‘구간’은 두 거점을 연결하는 경유지 전체다. 한 구간에 도로와 동굴이 여럿 있을 수 있다. ‘도로 번호’는 지방과 함께 기록한다. `S04` 같은 설계 노드를 4번도로라고 읽지 않는다.
- 표의 앞/뒤 화살표는 양방향 연결이다. ‘출구’는 **현재 맵의 화면 방향**이며 원작 방위가 아니다. 원작 북쪽 도시라도 현재 압축 배치에서는 다른 출구를 쓸 수 있다.
- 현재 지방 내부 통로는 모두 걷기/달리기 방식이다. 바다·동굴·사이클링로드를 참조 열에 썼다고 파도타기·자전거·공중날기·괴력 등의 필드 사용이 구현된 것은 아니다.
- 원작 참고는 신오 DP/Pt, 관동 FRLG/HGSS의 공통 지리와 차이, 성도 HGSS, 하나 BW/B2W2를 구분한다. 하나의 부채·모란만·기하는 B2W2 계열이며 BW 동선을 무조건 적용할 수 없다. 후속 설계 버전은 신오 Pt·관동 FRLG 지리/HGSS 표현·성도 HGSS·하나 B2W2다. 개별 버전 차이·사건 채택은 REFERENCE_RESEARCH에서 구분한다.
- ‘재구성/축약’은 현재 게임의 설명이다. ‘직접 대응 없음’에는 공식 번호를 억지로 붙이지 않는다. 미래 실제 맵을 분할할 때 기존 MapId·방향·도착점·조우 출처·저장 이행을 함께 검토한다.
- 지역 문서의 프로젝트 전용 번호가 이 기준과 충돌하면, 내부 관리 ID는 유지하되 플레이어 표시와 원작 설명은 이 문서 기준으로 수정한다.

### 시작 구간의 현재 연결과 남은 개정

목표는 Pt의 시작권역 지리를 복원하는 것이다. 아래 201·호수·잔모래·202 연결은 코드 반영·보행 미검증이며, 시작 마을 정체성과 가족/신규 스타팅 도입은 후속 이행이다. 기존 은솔 연구소·파트너 수령·가족/이웃 이야기와 저장 상태를 보존한다. [시작권역 상세](archive/2026-09-22-rebaseline/MAP_STORY_DESIGN.md#5-신오-영원-이후와-시작권역-복원)에서 미결정으로 남긴 프롤로그를 이름 변경만으로 확정하지 않는다.

1. 프롤로그 배치를 확정한 뒤 `town`의 떡잎마을 전환 또는 창작 연구마을 유지 방식을 결정한다. 현재 새잎마을은 프로젝트 장소로 설명하며, 두 시작 모드를 새로 구현하기로 확정한 것은 아니다.
2. `tour_sinnoh_route_201`을 신규 본선으로 두고 레거시 `route_s01`은 기존 저장 탈출용으로 보존한다. 새잎 서쪽 출구 `(2,15)`→201 도착 `(3,15)`, 201 서쪽 `(1,15)`→새잎 `(3,15)`다. 201 동쪽 출구 `(62,11)`→잔모래 도착 `(3,18)`, 잔모래 서쪽 출구 `(2,18)`→201 `(60,11)`다. 마른 본선 옆 Pt 낮 조우 풀밭 두 곳은 선택 경유다.
   - 호수 분기: 201 `(10,5)` 위쪽 진입→`tour_verity_lakefront` `(20,35)`; 호수근처 `(20,38)` 아래쪽→201 `(10,7)`. 호수근처 `(20,7)` 위쪽→`tour_lake_verity` `(28,44)`; 호수 `(28,46)` 아래쪽→호수근처 `(20,9)`. 모두 기존 도보 경유이며 본체·근처를 별도 MapId로 보존한다.
3. 잔모래 북쪽 출구 `(20,1)`→`tour_sinnoh_route_202` 도착 `(14,61)`, 202 남쪽 `(14,62)`→잔모래 `(20,3)`이다. 202 북쪽 `(14,1)`→축복 도착 `(14,33)`, 축복 남문 `(14,34)`→202 `(14,3)`으로 잇는다. 202는 굴곡 본선 옆 Pt 낮 조우 풀밭 세 곳과 Lv5 초보 트레이너 세 선택전을 두며 전투·승패가 출구나 귀환을 막지 않는다.
   - 잔모래 센터 문 `(9,11)`→`tour_sandgem_center` `(10,12)`; 실내 남문 `(10,15)`→마을 `(9,12)`. 연구소 문 `(29,13)`→`tour_sandgem_lab` `(12,14)`; 실내 남문 `(12,17)`→마을 `(29,14)`. 센터는 회복·PC 거점이고 연구소는 201/202 출신 보유 동료 기록을 비교한다. 최종 `createUnifiedWorld`는 출발 좌표·방향별 병합으로 이 문과 호수 분기를 보존한다. ID·좌표·지도 개정을 바꾸지 않아 이번 연결 보수에 별도 좌표 이행은 없다.
   - 축복의 원작 방향을 북 204·동 203·남 202·서 218로 맞췄다. `tour_sinnoh_route_202` 북쪽 출구는 축복 남문 `(14,34)`→도착 `(14,33)`, 축복 동문 `(38,24)`은 `tour_sinnoh_route_203`→도착 `(3,14)`이다. 203 서쪽 귀환은 축복 `(37,24)`에 도착한다. 과거 202 동문/203 남문 배치는 폐기했다.
4. `research_path`는 현재 창작 도보 연구길로 기록한다. 목표 본선은 `축복 → 218번도로의 육로·수상 구간 → 운하시티`다. 셔틀 전환은 별도 제안이며, 탑승 기능·목적지·왕복이 구현되기 전에는 셔틀로 안내하지 않는다.

각 장소를 추가/변경할 때는 이름·지방·원작/창작 구분·지형과 분위기·방문 이유·주요 시설·조우 방법·출구와 경유지·도착점·조건·귀환 방법을 함께 기록한다. 실내는 소속 도시와 층, 문/계단의 연결 상대를 기록한다. 현재 90권역 초안의 복합 노드(S17 세 호수 등)는 서로 떨어진 장소를 한 맵이나 직통 워프로 합치는 근거가 아니다.

`tour_lake` 하나에 진실·입지·예지호수를 합치지 않는다. 기존 MapId는 과거 저장 로딩용 허브로 남기고, 신규 `lake_verity`, `lake_valor`, `lake_acuity`에 각각 호수근처와 동굴을 둔다. 세 호수의 사건·전설 포켓몬 플래그도 서로 독립이어야 한다.

현재 `tour_verity_lakefront`→`tour_lake_verity`, `tour_valor_lakefront`→`tour_lake_valor`, `tour_acuity_lakefront`→`tour_lake_acuity`를 독립 적용했다. 각 본체는 둘레길과 중앙섬 전망, 건강한 파티 동료를 고르는 중앙 수면·동굴 방향 흔적 비교 활동까지 적용했다. 세 호수 기록은 서로 독립이며 HP·경험치·보상·통행에 영향이 없다. 수상이동·호수 동굴·전설 사건은 미구현이고 창작 `tour_lake`는 기존 저장과 관찰 기록용으로 보존한다.

### 관동 권장 확장안

관동은 도로 수 자체보다 **서로 다른 우회 구조**가 중요하다. 현재 채택 계약에서는 노랑시티 지상 관문과 동서 지하통로를 자유 통행으로 두고, 보라타운으로 가는 돌산터널 길과 연분홍시티로 가는 자전거길/해안길이 서로 다른 경험을 제공하게 한다. 원작식 노랑 검문 봉쇄는 현재 구현 지침이 아니다.

### 성도 권장 확장안

성도는 전통 도시만 배치해서는 느낌이 살지 않는다. 짧은 도로들이 촘촘히 이어지고, 숲·유적·탑·동굴이 생활권 바로 옆에 붙는 구성이 핵심이다.

## 6. 하나지방

하나 작업 시 기존 MapId와 레거시 연결 키 확인에는 [UNOVA_REGION.md 제5절](regions/UNOVA_REGION.md#5-도시-간-구간-대장)을 참고한다. 그러나 플레이어 표시명은 B2W2의 공식 1~23번도로·수로와 고유 지명을 따른다. 기존 프로젝트 1~7번도로·1~3번동굴은 내부 이행 키로만 남기며, 원작에 없는 구간은 새 번호 대신 창작 고유명을 사용한다.

따라서 현 문서의 “U-R04 해안길 확장 우선”은 취소한다. 같은 연결 슬롯을 재사용하더라도 결과물은 해안길이 아니라 **6번도로 + 전기돌동굴**이어야 한다. 또한 쌍용에서 기하로 직접 걸어가는 동굴은 원작 B2W2에 없으므로 물결·마린튜브와 기존 저장의 복구 경로를 구현하기 전에 현행 왕복을 임의 차단하지 않는다. 본편 개방 조건은 별도 설계한다.

## 7. 지방 간 이동 수단과 현재 이용 방법

확정된 큰 여행 순서는 **신오 → 관동 → 성도 → 하나 → 신오 귀환**이다. 현재 일반 이동망은 다음 네 노선을 양방향으로 제공한다. 일반 출구 이동에는 별도 CH·배지·자료·티켓 조건과 요금 차감이 없다. 초안 TR 이름은 의도한 교통의 명칭이며, 완성된 역무/승선 시스템이 있다는 뜻은 아니다.

### 운하–갈색 NPC 조사선은 별도

[sinnoh-story.ts](../src/sinnoh-story.ts)·[ferry-journey.ts](../src/ferry-journey.ts) 기준: 양쪽 도시의 ‘조사선 선원’과 대화 → 목적지 선택 → 1.8초 선박 이동 연출 → 상대 도시의 시작 위치 도착 → 자동 저장. 이용 조건은 `researchDelivered`, 왕복 무료다. 자료 수령·전달 조건은 STORY의 신오 네 배지 진행을 따른다.

머무르기/취소는 이동하지 않는다. 완료 시 `ferryPass=true`는 **이용 이력**이며 소모성 승선권이 아니다. 귀환도 선원에게 말하면 된다. 이 이벤트를 이용하지 않고 일반 출구로 관동에 갔다고 자료 전달·승선 완료가 되지 않는다. 실제 일반 교통에는 없는 잠금을 안내에 붙이지 않는다.

## 8. 도로 수 확장 기준

### 신규 지리 1순위 설계: 하나 6번도로와 전기돌동굴

#### A. 하나 6번도로

- 목표 크기: **40×88**(가로×세로 타일). 기존48×34~54×38 후보를 대체한다. 물풍경시티 쪽 진입과 전기돌동굴 쪽 출구 사이에 강·다리·연구소·쉼터가 차례로 보이도록 남북 길이를 확보한다.
- 시각 주제: 강을 따라 난 연구도로. 흙길·목재 다리·키 큰 풀·계절 연구소·동굴 앞 푸른 결정 조각을 사용한다. 바닷가·모래사장 타일은 제거한다.
- 진행 구조: 도보 본선과 선택 관찰 루프를 둔다. 강 건너 분기는 수상이동 지원 후의 확장 후보이며, 현재 무지원 기술을 통과 조건으로 붙이지 않는다.
- 상호작용: 계절 연구 전시와 동료 관찰을 우선 설계한다. 깜놀버섯 고정 조우·숨은동굴·계절 변화는 별도 시스템 후보이며 첫 도시 묶음의 필수 요구가 아니다.
- 조우 성격: 사철록·깜놀버섯·딱정곤 등 풀숲 생태를 중심으로 하고, 물가 조우와 흔들리는 풀을 분리한다. 정확한 레벨·확률은 현재 상한/지원종과 대조해 프로젝트 값으로 확정한다. 네 지방 전체의 완성된 레벨 곡선은 아직 없다.
- 출구 계약: 물풍경에서 진입한 안전점, 동굴에서 되돌아온 안전점, 다리/물 가장자리 충돌, 양쪽 표지판을 각각 검증한다.

#### B. 전기돌동굴

- 본선은1F **64×56**, B1F **56×48**의2맵이다. 선택B2F는 **48×48** 후속 후보로 분리한다. 원작의 모든 층을 복제하지 않아도 되지만 ‘빛나는 전기 결정’과 ‘결정을 밀어 길을 여는 퍼즐’은 반드시 남긴다.
- 시각 주제: 검은 암반, 푸른 전기석, 떠 있는 작은 결정, 가느다란 다리, 아래층이 보이는 낭떠러지다. 일반 갈색 암반굴 팔레트를 재사용하지 않는다.
- 퍼즐 구조: 입구 학습 결정·선택 보상자리·본선 퍼즐을 둔다. 결정 초기화와 저장 복원 정책을 상세 명세에서 하나로 정하고, 어떤 상태에서도 재시도·입구 귀환을 보장한다. 아이템 획득 기록은 결정 초기화와 분리한다.
- 조우 성격: 파쪼옥·철시드·기어르·저리어·암트르 계열처럼 전기·강철·동굴 생태를 대표하는 조합을 우선한다.
- 출구 계약: 6번도로 ↔ 1F 남부 ↔ B1F ↔ 1F 북부 ↔ 궐수시티를 왕복할 수 있어야 하며, 퍼즐 완료 전에도 입구로 귀환 가능해야 한다.

원작 B2W2와 BW의 입구 사건을 섞지 않는다. 2맵 축약의 1F 귀환 구조와 퍼즐·생태·상태 계약은 [맵별 상세 명세](archive/2026-09-22-rebaseline/MAP_STORY_DESIGN.md#4-하나-궐수-도착-묶음의-상세-명세), 원작 근거는 [U3·U4](reference/REFERENCE_RESEARCH.md#3-이번-설계에-사용한-원작-근거)를 따른다.

#### C. 기존 데이터 이행

- `tour_pass_driftveil_mistralton`은 삭제하지 않고 새 6번도로의 호환 MapId 또는 이전 저장의 리다이렉트로 사용한다.

20번수로 서단 `(1,18)`→홍련 서쪽 `(1,40)` 도착 뒤 상륙표 `(5,38)`가 전 층 표시·현지 동료·파티 상태를 읽고 `tour_cinnabar_center` 또는 `tour_cinnabar_hall`, 역방향 `tour_kanto_route_20`을 안내한다. 귀환 기록은 선택 반응이며 어느 방향의 워프도 잠그지 않는다.

홍련 외부의 기존 센터 문은 `tour_cinnabar_center` 28×22 재건 센터 입구 `(14,21)`/안전점 `(14,18)`으로 이어진다. 내부에는 기존 간호사 회복 `tourHost`와 PC `tourExhibit1`을 유지하고 20번수로·쌍둥이섬 귀환 동료 건조석, 남부 수로 귀환도, 화산재 돌봄 준비대를 배치했다. 귀환도는 동쪽 공식 20번수로와 북쪽 공식 21번수로 방향을 구분하되, 현행 북쪽 `tour_pass_pallet_cinnabar`가 원작 수상 지리를 도보 해안길로 재구성한 상태임을 직접 알린다. 새 워프·통행 잠금·즉시 이동은 없다.

홍련 외부의 기존 연구소 문은 `tour_cinnabar_hall` 28×24 공개 연구실 입구 `(14,23)`/안전점 `(14,20)`으로 이어진다. 서쪽 화산암 표본·동료 관찰판, 동쪽 지열 회로 모형, 중앙 귀환 기록대가 열린 바닥으로 연결되며 기존 `tourExhibit0/1/2` 사건을 유지한다. 내부 표지는 이 시설이 HGSS에서 존속한 원본 연구소가 아니라 넥서스의 복구 시설임을 밝힌다. 비공개 보호·제어 현장은 외부의 별도 조건부 출입구를 계속 사용하고 공개 연구실에 우회문을 추가하지 않았다.

홍련의 기존 상점·두 주택 문은 각각 `tour_cinnabar_mart` 24×20 입구 `(12,19)`/안전점 `(12,16)`, `tour_cinnabar_home1`·`home2` 24×18 입구 `(12,17)`/안전점 `(12,14)`으로 이어진다. 상점은 기존 점원 구매를 보존하면서 센터 회복→몬스터볼·상처약 확인→서쪽 상륙 데크→공식 20번수로 순서를 안내한다. 주택1은 해안 인계 뒤 동료 돌봄, 주택2는 쌍둥이섬 수첩과 북쪽 21번수로 대체 도보길·동쪽 창작 갈색 직결을 구분한다. 세 실내는 HGSS 원형 시설이 아니라 넥서스의 복구 생활 공간이며 출입·구매·통행을 사건 완료로 잠그지 않는다.

홍련 연구소 `tour_cinnabar_hall/tourExhibit2`에서 쌍둥이섬 동료를 선두로 준비하면 20번수로 서쪽 모래톱 `tour_kanto_route_20/route20HomewardKeeper`로 안내한다. 선택전 뒤 홍련센터·연구소 또는 동쪽 쌍둥이섬으로 계속 왕복하며 실제 참가 승리도 이동 조건이 아니다.

실제 참가 승리 뒤 재탐험은 홍련 수첩→쌍둥이섬 1F 서쪽 통로→B1F→B2F→B3F→B4F `tourSeafoamB4Cold` 실제 도달→동쪽 상승 회랑→홍련 연구소 순서다. 중앙 길찾기는 연결된 계단 사슬을 사용하며 재탐험 기록은 워프나 계단을 새로 열지 않는다.

1F~B4F 계단 그림은 각 워프의 현재 MapId 깊이와 목적 MapId 깊이를 비교해 상승/하강을 구분한다. 동쪽 귀환 표석도 B3F `(43,28)`, B2F `(43,29)`, B1F `(43,29)`, 1F `(43,37)`의 실제 조사 위치에 전용 방향 형태로 표시되며 좌표·충돌·워프는 그대로다.

방문 수첩은 `PASSAGE_PLACES`에 등록된 관동 19번수로·20번수로·쌍둥이섬 외부와 1F/B1F/B2F/B3F/B4F를 도시와 분리된 **도로·동굴 방문** 목록에 표시한다. 각 항목은 실제 MapId, 랜드마크와 방문 여부를 보존하고 길안내는 현행 워프 사슬을 사용한다. 이 목록은 새 연결이나 즉시 이동을 만들지 않는다.

층별 랜드마크는 외부 `쌍둥이섬 동쪽 동굴 입구`→1F `동서 출구도`→B1F `수로 얼음 능선 표석`→B2F `갈라진 얼음판 표석`→B3F `굽은 암반길`→B4F `깊은 냉기 관찰대` 순서다. 방문 수첩은 실제 오브젝트 이름이 일치하면 MapId뿐 아니라 해당 이벤트까지 안내한다. 20번수로 서쪽 항로표는 현재 연결된 홍련 상륙과 역방향 연분홍 귀환을 표시하며 과거 ‘도시 출구 미연결’ 문구는 폐기한다.

## 10. 개발 지도 표시 계약

- `src/region-atlas.ts`의 256×192 지도 좌표는 표시 전용이다. `PLACES.x/y`, MapId, 워프, 저장 좌표와 독립적으로 관리한다.
- 선은 `TOUR_NEIGHBORS`의 연결 개요이며 실제 보행 경로·교통수단·공식 도로 번호의 증거가 아니다. 도시/자연의 빨강/파랑 구분과 방문/현재 위치 표시를 유지한다.
- 도로·동굴의 세부 탐험 기록은 실제 MapId에 연결한다. 개발 지도 이동으로 파티·배지·포획·사건 플래그를 지급하지 않는다.
- 대표 장소를 추가하면 지도 표시 좌표도 정한다. 그림에서 런타임 경로를 역산하지 않는다.
- `tour_celestic`은 `PASSAGE_PLACES`와 대표 마커를 유지한다. 영원→봉신의 선은 211번도로 서쪽→동굴→동쪽을 요약하며 직통 워프가 아니다.
- 당시 입력·시각 검사 근거는 [개발 지도 기록](archive/SYSTEM_HISTORY.md#record-region_atlas)에 있다. 현행 QA 완료를 뜻하지 않는다.
