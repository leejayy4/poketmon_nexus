# Pokémon NEXUS — 현재 상태

**기준: 2026-09-22 구현 착수 후 코드·호출 경로 정적 검토.** 테스트·타입검사·빌드·브라우저·저장·시청각 QA는 실행하지 않았다. 아래 코드 존재·연결은 실제 플레이 통과와 다르다. 현재 작업 트리에는 이번 작업 이전의 미커밋·미추적 구현이 있다.

## 지금 무엇을 하는가

- 이번 구현: RB1 원본 보호·활성 사본·복구 UI, RB2 초기 호수/시설 연결 보존과 축복 시계 관찰의 설치·행동·시간·표현 연결. 코드 반영·미검증이다.
- 다음 제작: [로드맵](STORY_AXIS_ROADMAP.md)의 RB2 첫 구간 사건 등록 정리와 RB3 새 게임·신규 스타팅 진입. RB1/2 실행 수용은 QA 재개 뒤 별도로 한다.
- 제품·기술 방향: [NEXUS_GOAL](NEXUS_GOAL.md)의 HYBRID. 여러 지방의 새 지도를 동시에 늘리는 이전 운영을 후속 계획의 기본으로 삼지 않는다.
- 현행 QA 정책: **중단 유지**. 과거 재개/PASS 기록은 현재 허가나 품질 보증이 아니다.

## 기존 증거와 미검증

2026-09-20 보고에는 컴파일 복구·모듈 순환 해소·PP 수정, 당시 796통과/602실패와 일부 집중 검사가 기록돼 있다. 이는 [당시 보고](archive/SINNOH_HISTORY.md#record-nexus-cycle-and-oreburgh-20260920)의 결과다. 현재 트리의 PASS가 아니며 2026-09-22 미검증 코드가 추가됐다.

최근 구현은 [무쇠 통합 기록](archive/SINNOH_HISTORY.md#record-nexus-oreburgh-city-20260922)에 있다. 현재 실제 사용자 저장 위치·내용은 이번에 읽지 않았다. 기존 첫 배지 자연 진행 보고도 새 스타팅·새 경로·새 원고의 수용 증거로 승격하지 않는다.

## 협업과 보존 경계

구현 착수 시 앱의 현재 작업 목록에서 같은 저장소의 최근 별도 작업은 idle로 표시되었다. 이번 하위 작업은 저장/패널, 초기 연결, 시계 모듈, 정적 검토로 파일 소유를 나눴고 공통 엔진은 주 담당자가 통합했다. 과거 배정·잠금은 현재 명령으로 승계하지 않았다.

이번 구현은 기존 무쇠·동료·지역 작업과 문서 재편의 변경을 보존했다. 저장 보호·초기 연결·시계 회귀 검사 파일은 작성만 했고 실행하지 않았다. 소스/참고 자료 대조와 diff 공백을 검토했으며 테스트·타입검사·빌드·브라우저·저장·시청각 QA는 하지 않았다. scripts/public/설정/생성 데이터는 변경하지 않았다. 루트 AGENTS.md는 기존 삭제 상태다. 과거 배정·작업 위치·검사 이력은 [이전 인계](archive/2026-09-22-rebaseline/CONTINUE_STATE.md)와 [과거 통합 기록](archive/README.md)에 남겼다. 중복 상태 사본과 회차별 파일은 삭제했다.

이 파일은 최신 한 판만 유지한다. 구현 변경 뒤 해당 표의 근거·상태·남은 차이를 바꾸고, 고유한 실패·검증 근거는 archive의 해당 통합 기록에 남긴다. 과거 상태를 앞에 계속 붙이거나 회차 문서를 새로 늘리지 않는다. 다음 실행 작업은 로드맵에서 관리한다.
