# Pokémon NEXUS — 현재 상태

**기준: 2026-09-23 잔모래 재회·초반 포획/회복 순환 통합 후 코드·호출 경로 정적 검토.** 테스트·타입검사·빌드·브라우저·저장·시청각 QA는 실행하지 않았다. 아래 코드 존재·연결은 실제 플레이 통과와 다르다. 이번 이어받기 시작 시 작업 트리는 깨끗했으며 이전 구현을 기준선으로 보존했다.

## 지금 무엇을 하는가

- 이번 구현: 기존 RB1 저장 보호와 v2 도입을 유지하고 잔모래 센터 재회 → 실제 치료·볼 보급 → 선택 포획 안내 → 현지 동료 편성/성장 상담·실전 결과 → 귀환을 연결했다. Lv2 비버니의 저장 거부와 귀가 시 PP만 소모된 파티의 회복 누락을 수정했다. 코드 반영·미검증이다.
- 다음 제작: [로드맵](STORY_AXIS_ROADMAP.md)의 RB4에서 새 세 동료/201·202 출신 파티를 축복의 기존 사건과 다음 준비 구간에 연결한다. 새 지도 확대보다 초반 귀환·저장·메뉴 흐름의 남은 소스 결함을 우선한다. RB1~4 실행 수용은 QA 재개 뒤 별도로 한다.
- 제품·기술 방향: [NEXUS_GOAL](NEXUS_GOAL.md)의 HYBRID. 여러 지방의 새 지도를 동시에 늘리는 이전 운영을 후속 계획의 기본으로 삼지 않는다.
- 현행 QA 정책: **중단 유지**. 2026-09-12 사용자 운영 지시와 후속 재확인을 추적했다. 최초 중단 이유·만료 조건은 확보한 기록에 없어 폐기된 지시로 단정하지 않았다. 출처와 허용 범위는 [DEVELOPMENT §1](DEVELOPMENT.md#1-책임과-적용-범위). 과거 재개/PASS 기록은 현재 허가나 품질 보증이 아니다.

## 이번 시작 구간의 코드 연결

- [새 게임](../src/nexus-opening.ts)·[이름 입력](../src/nexus-profile.ts): 이름/파랑·산호 옷 → 난천 경기 중계 → 엄마의 빈 엽서 네 장과 반응 선택 → 은솔/하린 → 세 동료 선택 → 실제 연구소 출구 → 기존 집 앞 소개/산책 → 도윤의 일회성 출발 보급. 엽서는 별도 도입 플래그로 기록하며 배지용 `keyItems`에는 넣지 않는다. 취소는 수령/응답을 기록하지 않는다.
- [세 동료](../src/nexus-starters.ts): 900001 새록(풀·사슴), 900002 잿울(불꽃·늑대), 900003 포말이(물·물범). 이름·타입·수치·외형은 **제작용 잠정안**이다. 생성 입력·런타임·Lv5 수령·학습/PP·HP 성장·선택창/도감·앞/뒤 SVG 경로를 연결했다. 최종 디자인·진화·BW/BW2 애니메이션 완료가 아니다.
- [유진](../src/nexus-first-rival.ts): 첫 만남 뒤 비버니 Lv5와 선택 친선전. 실제 전투의 만남/시작/참여/종료/승리를 분리하고 승패와 중단 모두 도윤의 응급 처치로 HP/PP를 회복한다. 상금 없음, 승패 뒤 재대전 없음, 중단은 다시 제안. 이동 잠금 없음. 잔모래까지는 직접 걸어가며 자동 동행/이동은 없다.
- [잔모래 재회](../src/nexus-early-journey.ts)·[상태](../src/nexus-early-state.ts): v2 NEXUS 출발 후 센터 왼쪽 대기석의 유진이 첫 승부 승/패/미실시를 구분한다. 대화 완료는 재회만 기록하며 치료·포획을 대신하지 않는다. 기존에 막힌 대기석 `(3,9)`에만 NPC를 투영해 구형 저장의 합법 좌표를 추가로 막지 않는다. 안내 취소·저장 교체·장면 교체 콜백은 완료 효과를 내지 않는다.
- 간호사는 실제 HP/PP 회복 후 `nexusSandgemRested`를 기록한다. 첫 배지 전에는 몬스터볼을 최소5개까지 보충하고 기존 상처약 최소2개 보충을 유지한다. 초과 수량을 줄이지 않으며 기존 일회성 출발 지급을 재실행하지 않는다. 가방/전투의 볼 부족 안내도 접근 가능한 잔모래 센터를 가리킨다. 집에 돌아가 엄마에게 회복받을 때 HP가 가득해도 소모 PP를 복원하며 센터 복귀점은 유지한다.
- 202번도로 실제 표지의 선택 안내 → 기존 자연 풀밭 조우/전투/포획을 사용한다. 안내 완료, 실제 포획, 현지 동료의 실제 참가 승리를 별도 boolean으로 저장한다. 실제 포획/경험치 지급은 기존 전투가 담당하며 가짜 시범 포획·추가 보상·통행 잠금은 없다. 201에서 이미 포획한 동료도 파티/박스 현재 보유로 인식해 재포획을 요구하지 않는다. 센터 귀환 상담에서 선두·교대·경험치·기술/회복과 201 귀가/202 북진을 안내한다.
- 새 초반 상태는 v2에서 선택 필드로 읽어 이전 v2를 보존한다. 적재 시 만남·회복·포획 기록을 소급 생성하지 않으며 boolean 형태·출발 선행·상담의 재회 선행만 검사한다. 진행 조건에 현재 소유 슬롯을 저장하지 않아 PC 이동/파티 재배치로 과거 사실을 잃지 않는다.
- 기존 v1은 새 도입이나 신규종으로 자동 변환하지 않는다. `newSave()`는 구형 생성 계약, `Engine.freshSave()`는 `newNexusSave()`다. v2 읽기와 새 사본 활성화를 사용하며 실제 사용자 저장은 조회하지 않았다.
- 등록 순서는 체육관 특수 처리 → 일반 도로 트레이너 → 첫 여정 등록 → 도시/여행/일반 대사다. 무쇠게이트 작업자 배틀과 첫 배지 축하 우선순위를 보존했고 중복 호출을 제거했다. 축복의 다음 길은 실제 203번도로, 배지 뒤는 204·험한샛길·꽃향기 안내로 고쳤다.
- 장면 완료 콜백은 저장 객체/맵/좌표/장면 번호와 단일 실행을 검사한다. 새 이름 입력의 한글 조합·게임 키 충돌을 처리하고, 기존 리포트 확인으로 나가면 자동 재표시를 미뤄 복구/불러오기를 사용할 수 있게 했다. 필드·폼 화면은 아직 보지 않았다.
- 현재 시작 공간은 여전히 `town` **새잎마을과 기존 연구소**를 재사용한다. 수령 출처도 실제 표시명과 맞췄다. 떡잎/잔모래의 최종 공간 역할 분리·호수 원고 전체 연결은 남아 있다.

## 기존 증거와 미검증

이번 회차는 호출 순서·장면 완료/취소·저장 허용 조건·기존 HP 수식·이벤트 배치·길 안내를 독립 소스 리뷰했다. 새 포획 안내가 막힌 표지 칸으로 직접 이동을 요구하던 문제를 event 접근으로 고쳤고, 파티 상담 첫 페이지에서 취소해도 완료되던 효과를 제거했다. [early-capture-save](../tests/early-capture-save.test.ts)와 [nexus-early-journey](../tests/nexus-early-journey.test.ts)는 회귀 **원고**이며 실행하지 않았다. 전체 201/202 출현 종/레벨의 파티·박스 포획/사본 저장, Lv2→3 성장, v1/v2 호환, 실제 서비스 회복, 취소/재방문/길 안내를 QA 재개 뒤 확인해야 한다. 보행·장면 표시·입력·조우·패배 귀환·PC·자동 저장·재접속은 모두 미검증이다. 수정한 현행 문서8개의 로컬 링크233개는 누락이 없었고 diff 공백 확인도 통과했다. 이는 게임 실행 검사와 다르다.

2026-09-20 보고에는 컴파일 복구·모듈 순환 해소·PP 수정, 당시 796통과/602실패와 일부 집중 검사가 기록돼 있다. 이는 [당시 보고](archive/SINNOH_HISTORY.md#record-nexus-cycle-and-oreburgh-20260920)의 결과다. 현재 트리의 PASS가 아니며 2026-09-22 미검증 코드가 추가됐다.

최신 구현과 소스에서 확인한 결함은 [잔모래 초기 루프 기록](archive/SINNOH_HISTORY.md#record-nexus-sandgem-loop-20260923), 앞선 무쇠 작업은 [무쇠 통합 기록](archive/SINNOH_HISTORY.md#record-nexus-oreburgh-city-20260922)에 있다. 현재 실제 사용자 저장 위치·내용은 이번에 읽지 않았다. 기존 첫 배지 자연 진행 보고도 새 스타팅·새 경로·새 원고의 수용 증거로 승격하지 않는다.

## 협업과 보존 경계

이번 이어받기에서는 성장/포획 회귀 원고, 참고자료/독립 리뷰, QA 지시 출처를 하위 작업으로 나누고 엔진·상태·등록·저장 소비는 주 담당자가 통합했다. 기존 저장 보호 모듈·v1 도입·기존 지역/자산을 보존했다. 실제 사용자 저장은 읽거나 수정하지 않았다. 실행 QA·데이터 재생성·새 외부 자산·의존성·서버·자동화·커밋·푸시는 없다. 루트 AGENTS.md는 기존 삭제 상태다. 이전 도입/데이터 작업과 과거 검사 증거는 현재 실행 결과로 승격하지 않는다.

## 갱신 방법

이 파일은 최신 한 판만 유지한다. 구현 변경 뒤 해당 표의 근거·상태·남은 차이를 바꾸고, 고유한 실패·검증 근거는 archive의 해당 통합 기록에 남긴다. 과거 상태를 앞에 계속 붙이거나 회차 문서를 새로 늘리지 않는다. 다음 실행 작업은 로드맵에서 관리한다.
