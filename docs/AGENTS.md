# Pokémon NEXUS 작업 규칙

- 사용자 최신 요청이 우선한다. 문서 재정립 다음의 **게임 구현 착수**가 승인되었다. 현재 묶음은 로드맵과 인계를 따른다.
- 시작점은 [문서 안내](README.md)다. 작업에 필요한 기준과 해당 코드만 읽고 모든 문서를 매번 읽지 않는다.
- [비전·결정](NEXUS_GOAL.md), [확정 서사](story/NEXUS_MAIN_STORY_CANON.md), [현재 상태](PROJECT_STATE.md), [제작 순서](STORY_AXIS_ROADMAP.md)의 책임을 구분한다.
- 현행 기술 방향은 기존 기반을 활용하는 **HYBRID**다. 쓸 수 있는 구현을 선정해 점진적으로 이행한다.
- 루트 AGENTS.md의 기존 삭제 상태를 임의 복원하지 않는다.
- 미커밋·미추적 구현, 다른 작업자 변경, 사용자 실제 저장을 보존한다.
- 새 원고의 장 번호를 기존 MapId·포켓몬·이벤트·저장 ID로 기계 치환하지 않는다.
- 생성기 입력과 생성 결과는 [데이터 계약](RUNTIME_DATABASE.md)을 따른다. 파일명에 초안이 있다는 이유로 입력을 이동하지 않는다.
- 채택된 서사는 보존하고, 미결정 디자인은 추천과 이유를 기록한다. 통상적인 기술 세부는 담당자가 판단한다.
- 맵·서사·전투·이벤트·데이터·저장 구조를 검토하거나 개발할 때 [목적별 참고군](reference/REFERENCE_RESEARCH.md)을 적극 활용한다. 관련 원문·지도·소스를 읽고 채택/변경/미채택 이유를 남긴다. 단순 링크 나열로 조사를 대신하지 않는다.
- 외부 자료는 원작과 설계 선택을 대조하는 근거다. 넥서스의 채택 서사·플레이 목표·저장 호환에 맞게 판단하며, 매번 모든 자료를 읽거나 외부 엔진을 그대로 이식하지 않는다.
- 사건·생활·포켓몬 소유·보상·지리 조건을 분리한다. 선택 연작을 본편 통행료로 만들지 않는다.
- 한 번에 한 제작 묶음에 집중한다. 공통 파일의 쓰기 소유자를 정하고 같은 파일을 병렬 수정하지 않는다.
- 과거 배정·자동화 ID·회차의 다음 작업은 현재 실행 명령이 아니다. 실제 다른 작업과 겹치는지 먼저 확인한다.
- 커밋·푸시·배포·의존성 추가는 이번 범위에 포함하지 않는다.

## 검증과 도시 완료

- **현재 QA 중단 유지.** 명시적 재개 전 테스트·타입검사·빌드·브라우저·저장·시각/음향 QA를 실행하지 않는다.
- 문서 작업에서는 문서 링크·내용 일관성·diff 공백과 변경 범위만 확인한다.
- QA 재개 후에도 구현 중인 작은 기능마다 전체 검사를 반복하지 않는다.
- [제작 계약](MAP_STORY_DESIGN.md)의 도시 구현이 끝나면 관련 자동 검사와 도시 여정·귀환·저장·표현 확인을 묶는다.
- 첫 제작 구간은 도시별 수용에 더해 [첫 배지 구간](FIRST_BADGE_SLICE.md)의 새 게임부터 연속 플레이를 증명한다.
- 실제 저장 대신 분리된 QA 저장·사본을 쓴다. 코드 읽기, 자동 검사, 준비 저장, 자연 진행, 시각·음향 근거를 구분한다.
- 미검증은 완료가 아니다. 테스트 파일 존재·과거 PASS·맵 수·원고 분량을 현재 완료율로 쓰지 않는다.

## 문서와 인계

- 기준은 담당 문서 한 곳에서 수정한다. 같은 정책·상태·TODO를 여러 문서에 복사하지 않는다.
- 현재 사실은 PROJECT_STATE, 다음 실행 순서는 STORY_AXIS_ROADMAP, 짧은 재개 위치는 CONTINUE_STATE에 둔다.
- 상세 변경·실패·검증 근거는 archive의 관련 통합 기록에 남긴다. 회차별 파일·별도 검토함을 다시 늘리지 않는다.
- 중복·대체 문서는 필요한 내용을 담당 문서에 합친 뒤 삭제한다. 고유한 구현·실패·검증 근거와 이전 설계 대응만 archive에 남기고, 모든 문서의 전체 사본을 기본으로 만들지 않는다.
- 참고 자료와 생성 설계는 확정 기준을 덮어쓰지 않는다. 과거 문서의 ‘확정·최신·QA 재개’는 당시 기록이다.
- 새 문서를 만들기 전에 기존 담당 문서에 통합할 수 있는지 확인한다.
