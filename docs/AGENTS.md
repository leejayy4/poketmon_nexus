# 상세 작업 규칙

> **2026-09-12 사용자 지시: 모든 QA 일시 중단.** 사용자 명시적 재개 전까지 테스트·QA용 빌드·브라우저 플레이·시각/음향·저장 검증을 실행하지 않는다. 아래 도시 완료 QA 의무도 일시 정지한다. 진행 중 QA는 안전하게 중단하고 저장·작업·기존 결과를 보존한다. 구현 자체 중단은 아니며 미검증 상태를 유지한다.

맵 크기는 [맵 크기 기준·전체 대장](MAP_SIZE_STANDARDS.md)을 필수 참조한다. 현재 크기와 목표 크기를 구분하고, 도시·도로·실내·던전 각 층의 목표를 누락하지 않는다. 신규 목표값은 이 대장을 단일 기준으로 갱신하며 확대 적용과 QA는 도시 단위로 수행한다. 정사각형을 강제하지 않고 출구·해안선·거리·활주로·층별 탐험에 맞춰 가로세로 비율을 정한다.

실행·재개 절차는 [루트 AGENTS.md](../AGENTS.md)에 둔다. 이 문서는 구현 범위·보존·검증·인계의 상세 기준이다. 사용자의 최신 명시적 요청이 우선한다.

## 구현 범위

- [REFERENCE_RESEARCH](REFERENCE_RESEARCH.md)의 버전·조회 한계와 [MAP_STORY_DESIGN](MAP_STORY_DESIGN.md)의 공간·동료·스토리·이행 요구를 참조한다. 문서만 요청한 회차에는 코드·데이터·자산·저장·서버/자동화 설정을 변경하지 않는다.

- 성도 작업은 [JOHTO_REGION_GUIDE.md](JOHTO_REGION_GUIDE.md)를 필수 참조한다. 장소별 확장·포획/육성·시설 활동과 제5절의 도로/수로 번호·동굴 관리번호/고유명·경유 순서를 구현 명세에 반영한다. 이름만 바꾸어 구간 확장으로 처리하지 않으며, 공유 도로·실제 출입/귀환·길안내·저장 이행을 함께 설계한다. 본편·전설·새 잠금의 미확정 경계는 유지한다.

- 관동 작업은 [KANTO_REGION_PLAN.md](KANTO_REGION_PLAN.md)를 필수 참조한다. 장소별 생태·육성·실전·생활·맵 확장 기준과 도시 간 도로/동굴 번호·경유 순서를 적용한다. 기존 프로젝트 번호는 내부 별칭이며 신규 표시는 WORLD_ROUTES의 공식 번호·고유명을 따른다. 확장 예정 구역과 실제 맵을 구분한다. 변경한 연결은 대장·지도·표지·길안내의 일치와 기존 저장/출처 호환을 함께 확인한다. 번호 부여를 새 이야기·잠금 승인으로 해석하지 않는다.

- 신오 작업은 [SINNOH_REGION_PLAN.md](SINNOH_REGION_PLAN.md)를 지방별 보완·맵 확장·도로/동굴 번호의 기준으로 참조한다. 작업 지역과 경유 구간 번호를 명시하고 현재 MapId·워프와 대조한다. 신규 분리 예정 도로를 이미 구현된 것으로 안내하지 않으며, 표지·지도·NPC·도감 이름과 저장 호환을 함께 다룬다. 이전 번호는 현재 코드/이행 자료이며 신규 표시 기준은 WORLD_ROUTES다.

- Nintendo DS DP/플라티나풍을 유지한다. 지방을 상위 단위, 시티·마을 하나와 담당 진입/출발 구간을 완성 단위로 삼는다. 포켓몬 세계관에 맞는 맵·스토리의 실제 구현을 우선하고 준비·탐험·포획·성장·도시 경험·확정 체육관·다음 여행을 연결한다. 필요한 동선·실내 확장과 재배치는 허용한다.
- 승인된 기존 기능 보완, 지역 조우·트레이너·시설 활동, 현재 등장종의 기술·진화, 전투 규칙과 그래픽·음향을 현재 구간에서 사용할 최소 범위부터 구현한다. 전투 보강은 종별 능력치·물리/특수·속도/우선도·PP·주요 상태이상·포획 판정·AI를 단계적으로 다룬다.
- 새 인물·조직·라이벌·본편 사건·전설 획득 조건·엔딩·지역 잠금은 미확정 초안만으로 구현하지 않는다. 필요한 결정을 기록하고 독립적으로 진행 가능한 작업을 수행한다.
- [DEVELOPMENT.md](DEVELOPMENT.md)는 구현 계약, [STORY.md](STORY.md)는 확정 이야기와 플래그를 확인하는 문서다. 과거 수량·완료 보고·설계 DB는 현재 런타임의 증거가 아니다. 관련 코드를 대조한다.
- 첫 배지 작업은 [FIRST_BADGE_SLICE.md](FIRST_BADGE_SLICE.md)를, 기존 검증 근거는 [JOURNEY_IMPLEMENTATION.md](JOURNEY_IMPLEMENTATION.md)의 관련 기록을 참조한다. 사용자 최신 구간 지시를 과거 우선순위로 덮어쓰지 않는다.
- 하나지방 작업은 [UNOVA_REGION.md](UNOVA_REGION.md)를 필수 참조한다. 장소별 확장과 실제 플레이 묶음, 제5절의 기존 연결·내부 키를 대조하고 신규 지리는 WORLD_ROUTES와 MAP_STORY_DESIGN을 따른다. 구간 작업 시 지도·표지·안내원·진입 지명·조우 출처를 일치시키고 기존 저장 ID를 보존한다. 현행 직접 워프인 예정 도로 구간을 이미 존재하는 별도 맵으로 취급하지 않는다.

## 변경과 보존

- 공통 데이터는 [WORLD_DATA_STANDARDS.md](WORLD_DATA_STANDARDS.md)의 테이블 관계·출처 버전·실행 지원 범위를 기준으로 검토한다. 지방마다 같은 종·기술·아이템 효과를 복제하지 않으며 서식지·입수처·편성으로 차이를 둔다. 생성 문구는 생성기에도 반영한다.
- 지도·이동은 [WORLD_ROUTES.md](WORLD_ROUTES.md)의 실제 경유 MapId·양쪽 출구·수단·조건·귀환과 플레이어 표시명을 확인한다. 화면에는 원작 공식 번호·고유명을 우선하고, 원작에 없는 창작 구간은 고유명을 쓴다. 지방 문서의 프로젝트 번호는 내부 관리·저장 이행 자료로만 보존한다.

- 현재 도시의 맵·스토리·세계관 적용 목표를 유지하고 원인과 완료 조건이 분명한 하위 작업을 이어 수행한다. 부수 수정은 그 작업에 필요한 범위로 제한한다. 이미 구현한 기능을 재작성하거나 빈 지도·사용되지 않는 기반만 늘리지 않는다.
- 다른 작업자의 미커밋·미추적 파일, 사용자 실제 저장, 기존 ID·이벤트 플래그·포켓몬 ID와 유효한 진행을 보존한다. 저장 계약 변경에는 이전 저장 이행과 복원 검사를 포함한다.
- 승인된 범위의 작은 구현 수치·배치 결정은 기존 코드와 확정 설계를 근거로 판단한다. 의존성 추가·대규모 재작성·커밋·푸시·배포는 별도 요청 없이 하지 않는다.
- 기능 계약이 바뀌면 DEVELOPMENT.md·STORY.md 등 관련 절을 갱신한다. 생성 데이터는 해당 원본·생성 절차를 확인해 수정하며, 생성 성공을 게임 구현 완료로 보고하지 않는다.

## 검증과 도시 완료

2026-09-09 최신 사용자 지시의 단일 QA 기준이다. **도시·마을 하나의 계획된 맵·스토리·포켓몬·생활·연출과 담당 연결 구간을 모두 구현한 뒤 검증한다.** 과거 ‘매 작업 QA’, ‘기능 묶음마다 QA’, ‘구현 3회차 이내 QA’ 규칙은 폐기한다. 회차 수를 QA 예약 조건으로 사용하지 않는다.

- 개발 중: 필요한 코드 읽기·diff·문법/타입 등 작업 지속에 필요한 최소 확인만 한다. 작은 로직 변경마다 테스트 추가/실행, 전체 빌드, 브라우저 순회를 의무화하지 않는다. 저장·진행·전투를 건드렸다는 이유만으로 별도 QA 회차를 자동 시작하지 않는다.
- 실제 오류: 실행 불가·저장 손상·진행 막힘·명확한 오동작을 발견하면 해당 원인을 확인하고 수정한다. 필요한 재현·수정 확인만 수행하며 도시 전체 또는 새 게임부터의 QA로 확대하지 않는다. 확인한 실패를 숨기거나 다음 도시로 넘기지 않는다.
- QA 시작: [DEVELOPMENT의 도시 완료 조건](DEVELOPMENT.md#0-최우선-목표와-지방도시-작업-단위)에 정한 해당 도시 구현이 끝났을 때 전체 테스트·`npm.cmd run build`와 도시 단위 브라우저 플레이를 한 번에 수행한다. 작은 하위 기능 완료, 시간 경과, 회차 횟수는 시작 조건이 아니다.
- 도시 플레이: 직전 거점에서 진입 도로/동굴 → 도착 → 스토리·주민·포켓몬·핵심 시설 → 탐험·포획/육성 → 다음 출구·귀환을 확인한다. 적용한 범위의 취소·패배 복귀·저장/재접속, 그림·음향도 이 시점에 모은다. 원작의 전체 게임을 새 게임부터 반복하지 않는다.
- QA에서 발견한 도시 결함을 고친 뒤 영향받은 항목만 재확인한다. 무관한 전체 검사를 반복하지 않는다. 계획한 도시 경험과 검사에 미완료가 있으면 ‘구현 중’ 또는 ‘도시 QA 보완 중’으로 남기고, 통과했을 때만 ‘도시 완료’로 표시한다.
- 고유 `?qa=이름`과 사본 저장을 사용한다. 자동 검사, 준비 저장 플레이, 자연 진행, 시각 확인, 소리 청취를 구분하고 사용자 실제 저장을 보존한다. 도구·서버 문제로 못 한 항목은 미검증으로 기록한다.
- CONTINUE_STATE에는 지방·담당 도시·연결 구간 경계, 완료/남은 구현, 마지막 QA 근거, 다음 QA의 도시 완료 조건을 기록한다. 옛 구현 회차 수는 이력이며 현재 QC 카운터가 아니다. 이미 완료한 QA를 새 기준 때문에 다시 실행하지 않는다.
- 문서 전용 작업은 링크·내용 일관성·`git diff --check`만 확인한다. 게임 테스트·빌드·브라우저 QA를 실행하거나 도시 구현 진척으로 세지 않는다.

## 이어받기와 협업

- [CONTINUE_STATE.md](CONTINUE_STATE.md)는 직접 요청 작업의 인계, [PROJECT_STATE.md](PROJECT_STATE.md)는 총괄의 배정·쓰기 범위 기록이다. 후자는 총괄만 수정한다. 날짜·작업 상태·현재 파일을 대조하고 충돌한 배정을 임의로 해제하지 않는다.
- CONTINUE_STATE.md가 없으면 생성한다. 현재 지방·도시와 연결 구간 경계, 완료 변경/파일, 검사 결과, QA 식별자와 세이브 경로, 미검증/실패, 담당·쓰기 범위, 정확한 재개 위치, 다음 하위 작업과 도시 완료/QA 조건을 간결하게 기록한다. 상세 로그는 별도 보고서에 링크하고 오래된 본문을 계속 누적하지 않는다.
- 진행 중인 다른 담당의 인계를 덮어쓰지 않는다. 배정된 담당자는 자신의 보고서를 남기고 총괄이 공통 인계를 통합한다. 단순 질문·규칙 수정 때는 진행 중인 게임의 인계를 교체하지 않는다.
- 협업·자동 배정은 [AUTONOMOUS_WORKFLOW.md](AUTONOMOUS_WORKFLOW.md)를 따른다. 사용자의 직접 구현 요청은 실행 권한이며 총괄 회차 ID를 새로 요구하지 않는다. 기존 쓰기 범위와 겹치면 조율하거나 독립 작업을 수행한다.
