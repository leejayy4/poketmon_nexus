2026-09-07 최신 사용자 지시. 현재 대화가 Lead Developer/Orchestrator를 맡는다. 이전 5담당 순차 운영은 아래 4담당 병렬 검토 방식으로 대체한다.

## 역할과 경계

| 담당 | 첫 단계 | 구현 경계 |
| --- | --- | --- |
| Story | STORY.md·현재 진행·설정·대사·이벤트·복선 검토 | 코드 수정 금지. 확인된 사실·미결정 아이디어 구분. 코드 변경은 Core에 인계 |

**QA 에이전트는 사용자 지시로 정지 대상이며 신규 배정하지 않는다.** 기존 QA 작업 ID는 현재 제어 도구에서 찾을 수 없어 종료 명령 성공을 확인하지 못했다. 이 사실을 실제 중단 완료로 바꾸어 기록하지 않는다. Gameplay 검증 책임은 총괄이 맡는다.

## 회차 절차

1. 매 회차 AGENTS.md, docs/AGENTS.md, DEVELOPMENT.md, STORY.md, 이 문서와 PROJECT_STATE.md, 현재 Git 상태를 읽는다. 연결된 기획 DB·이전 인계도 필요한 범위에서 참조한다.
2. 먼저 네 역할에 읽기 전용 검토를 병렬 위임한다. 가능한 단순 분석·문서 검토는 가벼운 모델을 사용한다. Art는 별도 고유 QA 탭을 사용하며 다른 작업의 탭을 조작하지 않는다.
3. 총괄이 증거·영향·위험을 취합해 1~3개만 선정한다. 저장 손상·진행 막힘·실제 기능 불일치를 우선한다. 미결정 본편·대규모 시스템·불필요한 리팩터링은 확정하지 않는다.
4. 각 변경의 쓰기 파일 범위를 먼저 기록해 담당자에게 배정한다. 독립 파일만 병렬 수정하고 같은 파일을 둘이 동시에 수정하지 않는다. Story는 문서만 수정한다.
5. 담당 결과를 통합하고 총괄이 필요한 테스트·npm.cmd run build·변경 Gameplay의 실제 브라우저 검증을 마친다. 사용자 저장을 보존하고 ?qa=고유이름을 사용한다. QA 에이전트 정지는 테스트·브라우저 확인을 생략하는 지시가 아니다.
6. 관련 DEVELOPMENT.md/STORY.md와 docs/autonomy/<회차>.md, PROJECT_STATE.md를 갱신한다. 자동 테스트·직접 플레이·미검증을 구분한다. 결과를 읽고 다음 회차를 시작하며 후보 목록만 보고 끝내지 않는다.
7. 회차 실행 중에는 중복 배정하지 않는다. 남은 실패를 새 기능으로 덮지 않는다. 처리할 후보가 없으면 quiescent로 기록하고 자동화를 일시 중지한다.

## 구간 중심 배정 (2026-09-08)

- 상위 목표는 한 도시까지 여행하고 배지를 얻는 구간이다. 회차마다 고르는 1~3개 작업은 그 목표의 하위 작업이며, 기능 수나 테스트 수만으로 구간 완료를 판단하지 않는다.
- 현재 상위 목표·남은 플레이·막힌 지점을 PROJECT_STATE.md에 이어 기록한다. 부분 기능 완료 때 상위 목표를 새 아이콘·문구 작업으로 교체하지 않는다.
- 구간 직접 플레이를 먼저 수행하고, 발견된 여행·성장·도시·체육관 문제 중 영향이 큰 것을 선정한다. Story는 기존 사건 연결, Map은 이동과 방문 이유, Core는 성장·전투·저장, Art는 실제 장소와 기술 연출을 같은 구간 안에서 검토한다.
- 구현 후 해당 기능 검사와 구간 재확인을 구분한다. 필요한 구간 확대는 허용하지만 새 라이벌·탄갱 본편 등 미확정 이야기는 자동으로 확정하지 않는다.
- 구체적인 작업 순서와 구간 완료 기준은 [FIRST_BADGE_SLICE.md](FIRST_BADGE_SLICE.md)를 따른다. 문서만 바꾼 작업은 문서 검증으로 기록하고 런타임 구현이나 Gameplay 완료로 보고하지 않는다.
