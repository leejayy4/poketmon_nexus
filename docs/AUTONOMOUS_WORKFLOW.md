# 자율 개선 운영

2026-09-09 실행 규칙 정리. 직접 요청은 루트 AGENTS.md의 한 회차 절차를 따른다. 이 문서는 협업·자동 배정에 적용하며, 파일을 읽었다는 이유로 총괄 권한이나 자동화 실행 권한이 생기지 않는다. 아래 역할은 총괄이 위임할 때 사용한다.

## 역할과 경계

| 담당 | 첫 단계 | 구현 경계 |
| --- | --- | --- |
| Story | STORY.md·현재 진행·설정·대사·이벤트·복선 검토 | 기본은 이야기·문서 담당. 같은 도시의 이벤트 적용까지 필요하면 쓰기 범위가 배정된 구현 담당과 연결. 확정 이야기 구현을 문서 전용으로 영구 제한하지 않음 |
| Map / Content | 동선·NPC·탐험 요소·지역 구조 검토 | 확정 스토리 임의 변경 금지 |
| Core | 실제 코드·버그·미완성·구조 검토 | 선정한 범위만 구현. 유효한 저장과 기존 ID 보존 |
| Art / UI | 실제 화면·DP/플라티나풍 비율·애니메이션·시각 일관성 검토 | 게임 로직의 불필요한 변경 금지 |

**QA 에이전트는 사용자 지시로 정지 대상이며 신규 배정하지 않는다.** 기존 QA 작업 ID는 현재 제어 도구에서 찾을 수 없어 종료 명령 성공을 확인하지 못했다. 이 사실을 실제 중단 완료로 바꾸어 기록하지 않는다. Gameplay 검증 책임은 총괄이 맡는다.

## 회차 절차

1. 루트 AGENTS.md의 시작·재개 절차를 따른다. 매 회차 Git·배정·인계를 확인하고, 이미 읽은 문서는 변경된 규칙과 작업 관련 절만 다시 확인한다.
   하나지방 배정은 [UNOVA_REGION.md](UNOVA_REGION.md)의 장소별 기준·제5절 구간 대장을 필수 참조하고 대상 도시와 도로/동굴 키를 명시한다. 문서화된 향후 첫 묶음으로 현재 관동 배정을 자동 변경하지 않는다.
2. 단독 작업은 직접 수행한다. 사용자가 협업을 요청했거나 현재 배정에서 위임이 명시된 경우에만 필요한 역할을 나눈다. 네 역할의 매번 실행이나 Art의 별도 브라우저 QA를 의무화하지 않는다.
3. 총괄이 현재 지방·시티/마을 하나와 담당 도로/동굴 경계를 정하고 맵·스토리·포켓몬·디자인의 도시 완료 조건을 선정한다. 필요한 하위 작업만 나눈다. 저장 손상·진행 막힘·실제 기능 불일치를 우선하고 미확정 설정을 확정하지 않는다.
4. 각 변경의 쓰기 파일 범위를 먼저 기록해 담당자에게 배정한다. 독립 파일만 병렬 수정하고 같은 파일을 둘이 동시에 수정하지 않는다. 담당별 수정 범위는 이번 배정에서 명시하며 과거 문서 전용 역할을 현재 스토리 적용 금지로 상속하지 않는다.
5. 같은 도시의 구현을 통합하고 [도시 QA 기준](AGENTS.md#검증과-도시-완료)을 따른다. 도시의 계획된 구현이 끝난 뒤 총괄이 검증을 모아서 수행한다. 담당별/하위 기능별/회차 수별 전체 테스트·빌드·브라우저를 중복 실행하지 않는다.
6. 관련 구현 문서와 docs/autonomy/<회차>.md를 갱신하고 총괄이 PROJECT_STATE.md에 배정 결과를 통합한다. 직접 요청의 인계는 CONTINUE_STATE.md에 기록한다. 자동 검사·직접 플레이·미검증을 구분한다. 직접 요청은 한 회차 보고 후 종료하고, 자동 회차의 재개는 기존 승인된 스케줄을 따른다.
7. 회차 실행 중에는 중복 배정하지 않는다. 남은 실패를 새 기능으로 덮지 않는다. 후보가 없으면 대기 상태를 기록한다. 이번 요청만으로 자동화를 생성·변경·중지하지 않는다.

## 지속 실행

아래 ID·ACTIVE 표시는 과거 운영 기록이며 현재 실행 여부의 증거가 아니다. 운영 상태가 필요한 작업에서만 실제 도구로 확인한다. 일반 continue 요청은 자동화 설정 변경 요청이 아니다.

- 총괄 대화: 01a07ba0-4c4d-7ce2-bec7-9e95b886ddad
- 앱 heartbeat: qa / 포켓몬 개발 순환 · QA 제외 / ACTIVE / 5분 간격
- ID의 qa는 앱이 생성한 식별자이며 QA 담당 실행을 뜻하지 않는다.
- 이전 문서의 automation ID는 앱에 존재하지 않는다는 응답을 확인했다. 중복 생성 없이 새 heartbeat 하나를 생성했다.
- 주기는 완료 확인·다음 작업 재개 간격이다. 실행 중인 회차를 5분마다 다시 시작하지 않는다. 상태 변화가 없으면 조용히 유지하고 의미 있는 완료·실패·필요한 결정만 알린다.
- 앱·컴퓨터·작업공간·사용량과 도구가 사용 가능해야 지속 실행된다. 자동 배정 기록은 PROJECT_STATE.md, 직접 요청의 작업 인계는 CONTINUE_STATE.md에서 확인한다.

## 지방·도시 중심 배정

- 목표·우선순위·도시 완료 조건은 [DEVELOPMENT 제0절](DEVELOPMENT.md#0-최우선-목표와-지방도시-작업-단위), 검증 시점은 [AGENTS](AGENTS.md#검증과-도시-완료)만 관리한다. 과거 첫 배지 우선·3회차 QC 순환은 현재 배정 규칙이 아니다.
- [신오](SINNOH_REGION_PLAN.md)·[관동](KANTO_REGION_PLAN.md)·[성도](JOHTO_REGION_GUIDE.md)·[하나](UNOVA_REGION.md)의 해당 도시와 도로/동굴 명세를 읽고 맵·스토리 적용을 먼저 배정한다. 상점·메뉴·전투 기반만 계속 보강하며 실제 도시 작업을 미루지 않는다.
- Story·Map·Core·Art는 같은 도시 목표를 공유한다. 도시 외부·필수 실내·인접 도로/동굴·사건·포켓몬·생활·연출은 하위 작업이며 부분 완료만으로 다음 도시로 이동하지 않는다. 공유 통로는 소유 도시/구간 경계를 명시해 중복 제작을 피한다.
- 직접 인계는 CONTINUE_STATE의 최신 도시/저장, 협업 쓰기 범위는 PROJECT_STATE를 따른다. 과거 회차의 다음 작업으로 현재 진행을 되돌리지 않는다. 이미 검증한 기능은 변경 영향이나 실제 실패 없이 다시 QA하지 않는다.
- 미확정 큰 이야기·새 잠금은 분리하고, 확정된 원작 세계관과 기존 이야기의 구현은 계속한다. 첫 배지 문서는 그 도시가 대상일 때만 참조한다.
- 도시 완료 시 남은 필수 구현과 QA 항목을 확인하고 다음 도시·경계·재개 위치를 인계한다. 문서 전용 요청은 문서 정리로 마치며 게임 구현·도시 완료로 보고하지 않는다.
