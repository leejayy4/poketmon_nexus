## 공통 실행 요청

> 최신 AGENTS.md, DEVELOPMENT.md, STORY.md와 PROJECT_STATE.md를 읽고 현재 구현을 직접 확인한다. 담당 영역에서 가장 가치 있는 문제 1~3개를 골라 원인 확인 → 수정 또는 구현 → 관련 테스트와 빌드 → 실제 플레이 검증 → 문서 반영까지 마친다. 명확하고 위험이 낮은 문제는 개별 확인을 요청하지 않고 처리한다. 문제가 없으면 변경하지 않는다. 이번 배정만 수행하고 다음 후보와 근거를 남긴다.

## 실행과 인계

1. 총괄은 최신 작업 상태와 PROJECT_STATE.md를 읽는다. 같은 폴더에 다른 실행 중 작업이 있으면 새 수정 작업을 배정하지 않는다. 사용자 직접 작업이 우선이다.
2. 배정 전에 회차 ID, 담당 작업 ID, 목표와 상태 `dispatching`을 PROJECT_STATE.md에 기록한다. 기존 작업에 메시지를 보내고 성공하면 `running`으로 기록한다. 응답이 불확실하면 최근 메시지의 회차 ID를 확인하고 중복 전송하지 않는다.
3. 담당자는 해당 회차만 수행한다. 완료 시 `docs/autonomy/<회차-ID>.md`에 문제 근거, 수정 파일, 테스트 명령과 결과, 실제 QA URL·증거, 남은 문제, 다음 후보를 기록하고 최종 응답에도 요약한다. 보고서 작성만으로 프로젝트 전체 검증 완료를 주장하지 않는다.
4. 총괄은 `wait_threads`의 상태·커서를 사용한다. 실행 중인 담당에게 같은 요청을 재전송하지 않는다. 완료된 회차 보고서와 결과를 확인한 뒤에만 배정을 해제하고 다음 담당을 시작한다. `PROJECT_STATE.md`는 총괄만 수정한다.
5. 완료 판정은 관련 테스트·빌드와 필요한 실제 플레이 검증 근거가 있어야 한다. 실패·중단·환경 제한은 별도 기록한다. 동일 원인의 실패를 새 개선으로 덮지 말고 원인에 맞는 제한된 복구를 시도한다. 사용자의 결정이나 외부 복구가 필요하면 해당 문제를 보류하고 알린다.
6. 한 바퀴에 변경도 처리 가능한 후보도 없으면 `quiescent`로 기록해 자동화를 일시 중지한다. 사용자 요청으로 재개한다. 실행 중 상태에는 조용히 기다리고, 의미 있는 완료·실패·필요한 결정만 알린다.

## 자동화

총괄 작업을 5분 간격으로 깨우는 heartbeat 하나로 운영한다. 주기는 완료 확인 간격이며, 담당 작업을 5분마다 중복 실행하는 뜻이 아니다. 앱과 컴퓨터가 켜져 있고 프로젝트에 접근할 수 있어야 하며 계정 사용량·권한·도구 가용성에 따라 멈출 수 있다. 자동화 ID와 실제 활성 상태는 PROJECT_STATE.md에 기록한다.

이 문서는 개발 운영 규칙이다. 게임 런타임에 새 기능·이야기·저장 필드를 추가하지 않는다.
