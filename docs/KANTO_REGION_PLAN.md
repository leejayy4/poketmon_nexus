## 3. 공간과 플레이의 공통 기준

1. 시티·마을 하나와 담당 연결 구간에서 준비 → 탐험 → 포획·육성 → 도시 활동 → 다음 실전/여행을 완성한다. 체육관 미확정 때문에 독립적인 도로·생태·생활 보완을 멈추지 않는다.
2. 구간마다 기억할 지형 하나, 안전한 주 경로, 선택 샛길, 실제 만남/활동, 귀환·회복 동선을 설계한다. 샛길은 새 동료·관찰·실전·기존 도구 중 목적을 갖고, 모든 샛길에 보상을 강제하지 않는다.
3. 도시를 같은 크기로 일괄 확대하지 않는다. 현재 관동 도시의 34~40×30~36, 상록숲 20×18, 통로 기본 32×20은 시작 상태이며 상한이 아니다. 작은 마을은 생활 밀도, 큰 도시는 주거·상업·업무·항구 등 공간 분화, 숲·동굴·도로는 탐험 동선으로 확장한다.
4. 화면에서 읽히는 길·랜드마크·출구를 만든다. DS DP/플라티나풍의 타일·건물·인물 비율과 깊이 정렬을 유지하고, 해안의 파도·숲의 가림과 바스락거림·도시의 생활 움직임을 해당 기능 묶음에 포함한다.
5. 주민의 말, 필드에서 보이는 포켓몬, 실제 조우표·도감·학습/진화 정보를 맞춘다. 미구현 종·조우 방식·시간대를 이미 체험 가능한 것처럼 안내하지 않는다. 주민과 포켓몬의 식사·휴식·일·돌봄은 짧은 행동으로 표현하며 전부 의무 퀘스트로 만들지 않는다.
6. 레벨 상한은 숫자만 올리지 않는다. 다음 구간 상대·경험치·기술·진화·회복 비용과 기존 저장 복원까지 함께 다룬다. 현지 포획종을 파티에 넣고 다음 활동에서 사용할 이유를 만든다.

## 5. 도시 간 구간 번호와 경유 순서

### 5.1 번호 체계

K-R/K-C와 프로젝트 번호는 기존 연결의 내부 이행 키다. 아래 표의 ‘관동9=태초–홍련’·‘관동10=홍련–갈색’은 현재/옛 표시 기록이며 신규 표시에 사용하지 않는다. 공식9·10·돌산터널은 별도 보라 접근 설계다. 실제 수로를 만들기 전 태초–홍련과 홍련–갈색은 창작 해안길 고유명으로 구분한다.

### 5.4 게임에 번호를 반영할 때의 계약

1. 지역·공식 번호/창작명·양 끝 도시·경유 구역·맵 ID·조우 연결을 한 데이터 원본에서 관리하도록 구현한다. 도시 테마나 배열 순서로 번호를 자동 산정하지 않는다. 이 대장의 K-R/K-C 내부 키는 이행에 보존하되 옛 표시 번호를 신규 구간에 강제하지 않는다.
2. 장소 진입 배너, 양쪽 출입 표지, 지도/목적지 선택, 길안내·NPC, 도감 서식지에서 같은 구간명을 사용한다. 표지는 예를 들어 `관동 1번도로 / 태초마을 ↔ 상록시티`처럼 번호와 목적지를 함께 제공한다. 긴 이름은 줄을 나눠 DS 화면에서 확인한다.
3. 연속 경로 안내는 `태초 → 1번도로 → 상록`처럼 중간 구간을 생략하지 않는다. 숲·동굴·항로는 고유 구분을 유지한다. 실제 출입구 방향과 되돌아가는 도시도 안내한다.
4. 표시명 변경 때문에 `tour_*`, 획득 도구/트레이너 플래그, 도감·방문 기록, 기존 포켓몬의 `met` 출처를 일괄 치환하지 않는다. 기존 이름으로 저장한 포켓몬도 복원 가능해야 한다. 맵 분할·워프 변경은 이전 좌표·귀환점·길안내·출처 검증의 호환 처리를 포함한다.
5. 초안/생성 데이터는 원본과 생성 절차를 확인해 연결한다. K18/ENC-039를 다른 중앙 도로에 일괄 복제하지 않는다. 아직 조우 없는 풀밭을 새 서식지로 도감에 등록하지 않는다.

## 6. 구현 순서와 완료 기준

현재 관동 작업은 [CONTINUE_STATE.md](CONTINUE_STATE.md)의 갈색시티 구현 인계를 따른다. 태초 재개와 홍련 접근은 이전 이력이며 저장 사본과 도시 QA 결과를 합치지 않는다. 홍련의 남은 청취 확인도 별도 인계에 유지한다.

1. **갈색시티 완료:** 현재 부두·해안 접근로에서 주민/동료·터미널·주택·보급·운하 귀환과 다음 출구를 통합한 뒤 도시 QA를 수행한다.
2. **다음 신규 지리 후보는 보라 도착:** 블루 경계→공식9→10북→돌산터널→10남→보라 외부/필수 실내를 한 도시 목표로 설계한다. 옛 홍련–갈색의10번 표시는 창작 고유명으로 이행한다. 상세 요구는 [맵·스토리 설계 제6절](MAP_STORY_DESIGN.md#6-관동-갈색의-항구-경험과-보라-접근-복원)을 따른다.
3. **이후 도시별 확장:** 홍련의21번수로·섬 접근, 중앙/남부의 실제 도로·지하통로·도시를 분리한다. 새 관장·본편 사건·수상 이동 해금은 별도 채택 상태를 명시한다. 사용자 지정 도시가 있으면 해당 도시를 우선한다.

각 도시 작업에 구체화할 완료 기준:

- **길:** 번호·경유지·출구·귀환이 일치하고 안전 주 경로와 의미 있는 선택 공간을 이용할 수 있다. 옛 저장 좌표·귀환점의 유효성을 보존한다.
- **플레이:** 구현한 범위에서 포획/육성 또는 실전/도시 활동이 다음 여행에 쓰인다. 선언한 조우·기술·진화·도구 효과가 실제로 동작하며 중복 보상이 없다.
- **표현:** DS 화면에서 지형·랜드마크·명칭·생활 장면이 읽힌다. 음향을 변경하면 해당 재생 흐름과 가능한 청취를 확인한다.
- **검증·인계:** [도시 QA 기준](AGENTS.md#검증과-도시-완료)에 따라 해당 도시의 계획된 구현을 모두 마친 뒤 검증을 모아서 수행한다. 자동 검사·준비 사본·자연 플레이를 구분하고 CONTINUE_STATE에 다음 위치·남은 문제·QC 주기를 갱신한다.
