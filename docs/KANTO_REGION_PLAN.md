## 3. 공간과 플레이의 공통 기준

1. 시티·마을 하나와 담당 연결 구간에서 준비 → 탐험 → 포획·육성 → 도시 활동 → 다음 실전/여행을 완성한다. 체육관 미확정 때문에 독립적인 도로·생태·생활 보완을 멈추지 않는다.
2. 구간마다 기억할 지형 하나, 안전한 주 경로, 선택 샛길, 실제 만남/활동, 귀환·회복 동선을 설계한다. 샛길은 새 동료·관찰·실전·기존 도구 중 목적을 갖고, 모든 샛길에 보상을 강제하지 않는다.
3. 도시를 같은 크기로 일괄 확대하지 않는다. 현재 관동 도시의 34~40×30~36, 상록숲 20×18, 통로 기본 32×20은 시작 상태이며 상한이 아니다. 작은 마을은 생활 밀도, 큰 도시는 주거·상업·업무·항구 등 공간 분화, 숲·동굴·도로는 탐험 동선으로 확장한다.
4. 화면에서 읽히는 길·랜드마크·출구를 만든다. DS BW·BW2풍의 타일·건물·인물 비율과 깊이·움직임으로 이행하고, 해안의 파도·숲의 가림과 바스락거림·도시의 생활 움직임을 해당 기능 묶음에 포함한다.
5. 주민의 말, 필드에서 보이는 포켓몬, 실제 조우표·도감·학습/진화 정보를 맞춘다. 미구현 종·조우 방식·시간대를 이미 체험 가능한 것처럼 안내하지 않는다. 주민과 포켓몬의 식사·휴식·일·돌봄은 짧은 행동으로 표현하며 전부 의무 퀘스트로 만들지 않는다.
6. 레벨 상한은 숫자만 올리지 않는다. 다음 구간 상대·경험치·기술·진화·회복 비용과 기존 저장 복원까지 함께 다룬다. 현지 포획종을 파티에 넣고 다음 활동에서 사용할 이유를 만든다.

## 5. 도시 간 구간 번호와 경유 순서

### 5.1 번호 체계

K-R/K-C와 프로젝트 번호는 기존 연결의 내부 이행 키다. 아래 표의 ‘관동9=태초–홍련’·‘관동10=홍련–갈색’은 현재/옛 표시 기록이며 신규 표시에 사용하지 않는다. 공식9·10·돌산터널은 별도 보라 접근 설계다. 실제 수로를 만들기 전 태초–홍련과 홍련–갈색은 창작 해안길 고유명으로 구분한다.

`K01~K20` 설계 권역·ENC 조우표·MapId와 공식 번호를 분리한다. 새 맵은 WORLD_ROUTES의 공식 지리 또는 명시적 창작 구간으로 등록하고 레거시 번호를 늘려 화면에 노출하지 않는다. 기존 출처·위치·flags 이행은 MAP_STORY_DESIGN을 따른다.

### 5.2 연결 대장

화살표는 양방향 경유 순서다. 동서남북 출구 좌표는 현행 워프를 확인하며, 이 표의 작성 순서를 실제 화면 방위로 해석하지 않는다. 조우 없음은 문서 작성 시 실제 런타임 풀 미연결을 뜻한다.

`cinnabar-rescue-work.ts`의 실제 현장 선택으로 보호 공급 유지, 남쪽 로비 조사→동쪽 확인대 복귀의 대피 본선 정찰, 상대 현장 확인→유진 보고 확인을 연결했다. `nexusCinnabarProtectionReady`/`nexusCinnabarEvacuationReady`는 각 준비 결과, `nexusCinnabarEvacuationWalkChecked`는 남쪽 합류 부분 확인, `nexusCinnabarPartnerWorkChecked`는 상대 현장 조사만 뜻한다. 역할 분담만으로 준비 결과를 만들지 않는다.

준비 두 조건 뒤 경비 `(24,12)`의 기존 종/공통 트레이너전(ID `cinnabar-control-guard`,알통몬24/꼬마돌25)을 거쳐 단말 `(25,8)`에서 제어 신호만 분리하고 확인 대화를 끝내야 `nexusCinnabarControlSeparated`를 저장한다. 미승리에는 단말 조작만 막고 남문·모든 보행/귀환은 유지한다. 완료 준비와 실제 승리는 귀환/패배 뒤 보존한다. 동적 장치 그림과 단계별 objective는 중앙에서 현재 상태로 연결했다. 테스트·빌드·브라우저·저장·시청각 QA 전부 미실행이며 실제 완료 검증과 구분한다.

#### 개체 대피·해안 인계 적용 — 2026-09-13

`cinnabar-evacuation.ts`와 순수 `cinnabar-evacuation-state.ts`를 지역 생활 핸들러/중앙 getMap·engine.map·NPC 렌더러/단계별 목표에 연결했다. 원본·두 준비·제어분리 뒤 각 포켓몬을 보호 구역→동쪽 지점→남쪽 로비→외부 해안→개별 인계 순서로 실제 위치에서 확인한다. 피카츄는 `(18,23)`→`(33,23)`→`(18,42)`→외부 `(40,40)`, 알통몬은 `(23,23)`→`(35,24)`→`(22,42)`→외부 `(43,40)`다. save flags의0~4단계로 NPC를 재구성하며 원본 NPC 객체를 수정하거나 파티/박스에 추가하지 않는다. 단계별 재배치이고 뒤따라 걷는 프레임 애니메이션은 아니다.

첫 로비 도착 뒤 뮤츠가 자발적으로 간섭을 막는 별도 장면과 전용 형상을 연결했다. `nexusCinnabarMewtwoAssisted`는 도움 목격이며 포획/보상이 아니다. 두 개체의 해안 stage4와 선행 조건 뒤 유진 `(42,41)`의 확인 대화만 `nexusCinnabarShoreHandoffComplete`를 생산한다. 개체들은 실내에서 제외되고 해안에서 쉬며 취소/귀환/재접속은 마지막 저장 단계를 기준으로 한다. 중앙의 같은 순수 projection은 getMap 및 roaming 우선 최종 맵에도 적용돼 상태를 현재 저장으로 읽는다.

해안 작은 결말은 연결했지만 CH03 전체 완료는 아니다. 이안의 납품 기록→성도 연결과 연구진 업무 변화가 남아 있다. 실프 원본/준비/제어/뮤츠 도움/개체 대피/해안 인계를 하나의 완료 플래그로 합치지 않는다. 실제 재접속·NPC 중복/유실·보행·시각/음향 QA 모두 미실행이며 자세한 상태 키와 소비는 관동 인계 최신 항목을 따른다.
