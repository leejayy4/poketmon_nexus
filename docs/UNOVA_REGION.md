> 2026-09-10 조사 반영: [하나 맵별 스토리 요구](MAP_STORY_DESIGN.md#4-하나-궐수-도착-묶음의-상세-명세) · [웹 근거와 기준 버전](REFERENCE_RESEARCH.md). 아래 번호/현행 연결 대장은 이행 자료이며 신규 지리 본선이 아니다. 현재 도시 구현/QA를 마친 뒤 제2절의 신규 도시 후보를 선택한다. 날짜별 PASS·미완료는 당시 이력으로 보존한다.

최신 확인: 2026-09-12. 하나지방 보완 방향과 프로젝트 전용 이동 구간의 기준이다. 구름시티·4번도로 리조트데저트 선택 접근은 제2절의 최신 적용 범위까지 런타임에 반영했고 도시 QA 대기 중이다. 다른 장소의 확장 계획과 미분리 도로는 구현 완료로 취급하지 않는다.

> **QA 일시 중단(2026-09-12):** 사용자 지시에 따라 전체/부분 테스트·빌드 반복·브라우저 QA·음향 확인을 중단한다. 아래 검증 기록은 중단 전에 확보한 이력이며, 사용자가 QA 재개를 명시하기 전에는 새 검증이나 도시 완료 판정을 수행하지 않는다. `continue`는 하나지방 구현과 문서 적용을 계속한다.

## 1. 적용 범위와 읽는 순서

- 하나지방의 맵·조우·시설·트레이너·그래픽·음향·진행을 작업할 때 이 문서를 먼저 읽고, [DEVELOPMENT.md](DEVELOPMENT.md)·[STORY.md](STORY.md)의 현재 계약과 해당 소스를 대조한다.
- 네 지방 공통 종·기술·저장 정책은 [WORLD_DATA_STANDARDS.md](WORLD_DATA_STANDARDS.md), 현행 전체 연결과 원작 지리 비교는 [WORLD_ROUTES.md](WORLD_ROUTES.md)를 함께 참조한다. 제5절은 레거시 연결 자료이며 신규 지리·표시는 WORLD_ROUTES의 B2W2 기준을 따른다.
- 목표는 **도시에서 준비 → 도로·자연 구역 탐험 → 포획·육성 → 다음 도시의 회복·생활 활동 → 도전 → 다음 여행**이다. 하나지방 전체를 한 번에 구현하지 않고 실제로 사용할 여행 구간으로 나눈다.
- DS DP/플라티나풍을 유지한다. 하나의 도시·생태·생활 개성은 지형, 건축 배치, 포켓몬과 주민의 행동, 활동, 소리로 표현한다.
- 새 인물·조직·라이벌·본편 사건·전설 획득 조건·배지 선후관계·지역 잠금은 이 문서로 확정하지 않는다. 관련 결정이 필요한 부분을 분리하고 독립적인 맵·생활·탐험 보완을 진행한다.
- 기존 [초안 맵의 하나 권역](개발용_초안맵.md#7-하나지방--도시의-선택과-오래된-용) U01~U20, CH/SQ/PG 및 설계 DB는 미래 설계다. 원작 지리나 현재 MapId와 같은 것으로 취급하지 않는다. 이 문서의 현행 연결 대장과도 구분한다.

## 2. 현재 구현 기준선

### 최신 QA — 갤러리 연속 활동 확인 (2026-09-10)

별도 빌드5190의 준비 사본에서 서쪽 항만 스케치→갤러리까지 도보→그림 비교→빛과 그늘 선택→저장/재접속 후 선택 대사 복원을 직접 확인했다. 빌드 통과. 정원 포획 동료의 실제 PC 인출/기술 활용·치릴리 표시·청취와 공통 실패의 구름 영향은 남았다. [최신 인계 8단계](CONTINUE_STATE.md)를 따르며 도시 완료로 표시하지 않는다.

### 이전 QA — 항구 조사·동료 활용 (2026-09-10)

구름 전용4개 검사 통과: 항만 세 조사면의 확인 입력→기록 복원→갤러리 목록, 두 정원 종의 준비 포획/박스 인출/주택 기술 학습/출처 복원 포함. 브라우저는 서쪽 항만 스케치 기록과 갤러리 안내 선택까지 확인했다. 실제 연속 갤러리 방문·포획 동료 인출/육성·청취는 미완료이며 [최신 인계 7단계](CONTINUE_STATE.md)를 따른다.

### 이전 QA — 정원 실제 포획 (2026-09-10)

별도 준비 사본에서 풀밭 이동→콩둘기 Lv24 실제 조우→볼 사용→PC 박스 포획 전송, 만난 장소 표시, 저장/재접속 후 도감 포획 수 복원을 확인했다. 치릴리·박스 개체 육성·갤러리 연속 플레이·청취와 공통 실패 분류가 남았다. 전체 재검사 622개 중610 통과/12 실패였고 그중 사막 연결 검사2개를 수정 후 통과했다. [최신 인계 6단계](CONTINUE_STATE.md)를 따른다.

### 이전 적용 — 주택 생활과 도시 QA (2026-09-10)

동쪽 2동·6개 층에 그림 작업실/정원 동료 주거 역할, 선택 스케치 반응, 실제 파티 기술 준비와 길안내를 적용했다. 주택 초기화 순환 참조를 수정했다. 빌드·구름 전용 검사 2개와 준비 사본의 주택 진입/재접속은 통과했으나 전체 검사 실패 분류·자연 포획·도시 연속 플레이·청취가 남아 있다. **도시 QA 보완 중**이며 [최신 인계](CONTINUE_STATE.md)의 5단계를 따른다.

### 최신 적용 — 구름 정원 포켓몬 (2026-09-10)

구름 북쪽의 선택 풀밭 두 곳에 콩둘기/치릴리 낮 Lv22~24·60/40을 연결했다. ENC-061의 B2W2 구름 서식 근거를 선택했고 배치·레벨·비중은 프로젝트 값이다. `met`는 `구름시티 북쪽 정원`, 4번도로 사막 입구 조우는 없다. 두 종은 BW2 습득표의 지원 기술과 BW 앞뒤 96px 스프라이트를 사용하며 다른 종의 플라티나 습득표는 유지한다. 두 종 진화는 미구현이다. 정원 앞 피카츄는 야생종이 아닌 산책 동료다. 주민이 실제 서식지·보유 도구를 안내하고 정원/센터/상점/갤러리/4번도로 사막 입구로 길을 안내한다. 타입·생성/표본·자산만 최소 확인했으며 자연 조우/포획과 도시 QA는 미실시다.

### 최신 적용 — 갤러리 항구 산책 (2026-09-10)

갤러리 안내원과 「항구의 아침」에서 세 수면의 도보 안내를 선택하고, 현장에서 건강한 선두 동료와 풍경을 남겨 갤러리 그림과 비교할 수 있다. 하나 이상의 스케치 중 마음에 남은 풍경을 골라 저장한다. 스케치는 관찰 시 동료 종과 풍경에 대한 텍스트 기록이며 별도 이미지 생성이 아니다. 세 곳 완주·현지 포획·보상·통행 조건을 추가하지 않는다. 기록은 지방 방문/본편 해결과 구분한다. 타입 검사만 완료, 기능 동작과 도시 QA는 아직 미검증이며 지역 포켓몬·생활/실내 통합이 다음 작업이다.

### 최신 적용 — 4번도로 · 리조트데저트 입구 (2026-09-12)

- **QA 중단 뒤 추가 구현:** `tour_unova_route_04` 36×88 본선과 `tour_join_avenue` 28×64를 추가했다. 이동 순서는 구름 동쪽→4번도로 남쪽→조인애버뉴→뇌문이며, 기존 `tour_unova_route_01`은 4번도로 동쪽에서 빠지는 리조트데저트 선택 접근으로 재배선했다. 사막↔뇌문 직접 워프는 제거했다. 사용자 지시에 따라 테스트·빌드·브라우저 검증은 수행하지 않았다.
- 지역 지도 인접 관계도 실제 워프에 맞춰 구름↔뇌문 본선과 구름→4번도로→사막 선택 목적지로 바꿨다. 4번도로와 조인애버뉴의 각 안내판은 좌표·출구 방향·즉시 목적 MapId를 야외 장소 데이터에 함께 등록한다. 따라서 상위 지도, 길 안내 버튼, 근접 표시가 옛 사막↔뇌문 직결을 안내하지 않는 것이 구현 계약이다. 이 항목은 QA 중단 중 적용되어 미검증이다.
- 4번도로에는 모래바람 관측 말뚝·분기 공사 표본·사막 포켓몬 발자국판을 두고, 조인애버뉴에는 구름 항구 교환대·사막 탐사 진열대·파트너 휴게 창구·뇌문 공연 게시판·여행자 교류 기록을 배치했다. 구매·회복·보상 기능을 만들지 않고 두 도시와 사막의 생활·생태가 이어지는 조사 지점으로 적용했다. QA 중단 중 구현되어 접근성과 표시는 미검증이다.

## 3. 하나지방에 적용할 플레이 기준

### 3.1 서식지와 동료의 성장

- 사막·항구·공업 외곽·들판·숲·산지·해안의 조우를 구분한다. 풀밭 그림만 두고 조우가 있는 것처럼 안내하지 않는다.
- 종은 원자료와 설계 DB에서 해당 지역에 맞는 후보를 확인한다. 구현 단계에서 정확한 종·비중·레벨·기술·진화·앞뒤 그림을 한 묶음으로 정한다. 다른 지역 풀을 편의상 복사하지 않는다.
- 새 동료가 다음 전투에서 기술·상성·교대로 역할을 갖게 한다. 모든 종 완성보다 선정한 종의 포획→편성→성장→활용을 먼저 연결한다.
- 거리 포켓몬은 주인과 일하거나 쉬고 놀도록 표현한다. 거리 전시, 야생 포획, 선물의 출처와 소유 처리를 구분한다.

### 3.2 탐험과 도시 생활

- 통과길, 선택 조우 샛길, 트레이너가 있는 길을 구분한다. 분기는 관찰·동료·도구·풍경 등 방문할 이유를 갖고, 복귀 지름길 또는 합류점을 제공한다.
- 시설은 설명 읽기에서 끝내지 않고 도시 고유의 선택·조작·동료 활용으로 연결한다. 모든 도시에서 같은 수첩·파티 검사·보상 수령을 반복하지 않는다.
- 회복·구매·PC·기술 편성이 도착 후 정비와 다음 출발로 이어져야 한다. 희귀종 포획이나 선택 생활 활동을 필수 출구 조건으로 삼지 않는다.
- 도시마다 접근 풍경, 건축 윤곽, 거리 폭, 지면, 생활 소리와 이동 리듬을 다르게 한다. 글로만 도시의 차이를 설명하지 않는다.

### 3.3 전투와 장기 여행

- 일반 트레이너는 지역과 직업에 맞는 팀 및 서로 다른 전술을 갖는다. 선택 도전·패배 복귀·재접속과 중복 보상을 함께 설계한다.
- 체육관은 준비할 이유·실내 경험·관장전·도전 뒤 다음 여행을 묶는다. 미정인 관장 이름·팀·필수 배지 순서는 구현 전에 결정 항목으로 남긴다.
- Lv.25 상한을 단순히 높여 처리하지 않는다. 기존 파티를 유지한 지방 이동, 새로 잡은 동료의 합류, 경험치·기술 습득·진화·상대 레벨을 함께 검토한다.
- 속도·우선도, PP, 주요 상태이상, 종별 능력치와 물리/특수 구분 등은 해당 구간에서 실제 선택을 늘리는 최소 범위부터 구현한다. 미구현 효과를 대사나 미리보기에서 지원하는 것으로 표시하지 않는다.

| 기하↔운하 지방 연결편 | `tour_humilau` 서쪽 ↔ `tour_canalave` 남쪽, 직접 워프 | 도로·동굴 번호 없음. 기존 조사선 사건과 새로운 승선 조건을 혼동하지 않음 |

### 5.5 플레이어에게 구간을 표시하는 계약

구간을 실제 구현할 때 아래 표시를 한 번에 연결한다. 2026-09-12 현재 구름→4번도로→조인애버뉴→뇌문, 뇌문→5번도로→물풍경도개교→물풍경, 물풍경→6번도로→전기돌동굴→궐수의 지도·표지 문구를 실제 MapId 연결과 함께 이행했다. 모두 QA 중단 중 적용되어 미검증이다.

1. **도시 출구 표지와 안내원:** 뇌문 서쪽은 `5번도로 · 물풍경도개교 / 물풍경시티`, 물풍경 북쪽은 `6번도로 · 전기돌동굴 / 궐수시티`처럼 실제 첫 경유지와 최종 목적지를 함께 표시한다. 도시 출구 방향과 도로 전체의 원작 방위를 구분한다.
2. **지도·길안내:** `뇌문시티 → 5번도로 → 물풍경도개교 → 물풍경시티`, `물풍경시티 → 6번도로 → 전기돌동굴 1F 남부 → B1F → 1F 북부 → 궐수시티`처럼 등록된 MapId만 순서대로 보여 준다. 구현되지 않은 맵을 길안내 노드로 표시하지 않는다.
3. **구간 진입과 내부 표지:** 진입 시 번호와 고유 지명, 내부 이정표에는 양쪽 실제 출구의 목적지·방향을 표시한다. 동굴 분할 시 층명과 출구 방면도 표시한다.
4. **도감·포획 장소·저장·재방문:** 번호를 조우 바인딩과 표시명에 연결할 때 기존 `met` 검증과 저장 복원·방문 기록을 함께 확인한다. 예전 포획 장소 문자열을 새 표시명 때문에 거절하지 않는다.
5. **현재 상태 안내:** 조우 미지원 구간은 야생 포켓몬이 나온다고 안내하지 않는다. 도로·동굴 번호는 위치 식별자이며 배지·이벤트 완료·통행 잠금을 뜻하지 않는다.

표시 예시의 줄바꿈은 기존 DS 대화창 폭에 맞춰 구현한다. 정적인 문구마다 다른 방향·목적지를 복사해 넣기보다 동일한 연결 데이터에서 읽도록 한다.

## 6. 우선 구현 묶음과 완료 조건

현재 하나 작업은 [궐수 도착 묶음](MAP_STORY_DESIGN.md#4-하나-궐수-도착-묶음의-상세-명세)이다. 6번도로·계절 연구소·전기돌동굴 본선과 저장형 결정 밀기, 궐수 외부·필수 실내·도시 이야기·콩둘기 생활 표현을 적용했다. 계획 범위는 정적으로 적용됐으며 조우·아이템·선택 B2F는 후속 범위다. QA는 사용자 재개 전까지 실행하지 않으므로 궐수 완료 확정도 보류한다. 사막 필수 관통을 유지하는 옛 뇌문 진입 요구는 폐기했고 4번도로 본선·조인애버뉴·사막 선택 분기를 적용했다.

맵마다 공간·포켓몬·행동·상태·귀환을 적고 도시 전체가 끝나면 QA한다. 기존 위치·파티/박스·met·flags를 보존하며 신규 경유지를 추가하기 전에 대체 왕복·이행표를 준비한다. 원작 PWT·플라스마단·체렌·항공 해금은 현재 코드에 없는 별도 스토리 채택안이다. 자료 조사만으로 통행을 차단하지 않는다.

## 7. 구현 인계와 문서 유지

- 구현 회차 시작 시 대상 도시와 제5절 구간 키, 완료 조건 2~4개, 변경 파일 범위를 짧게 적는다.
- 맵·연결: `src/explore-world.ts`, `src/explore-expansion.ts`, `src/explore-layouts.ts`, `src/journey-world.ts`, `src/journey-route-layouts.ts`, `src/unified-world.ts`와 실제 지도·표지·길안내를 대조한다.
- 포켓몬·활동: `src/runtime-encounters.ts`, 원본 설계와 추출기, `src/road-trainers.ts`, `src/city-activities.ts`, `src/journey-services.ts`, `src/explore-pokemon.ts`의 관련 부분을 확인한다.
- 생성 데이터는 원본→생성기→런타임 추출 순서를 따른다. 문서 번호를 기존 MapId나 U01~U20 설계 노드에 직접 덮어쓰지 않는다.
- 구현 후 이 문서의 해당 행에 실제 MapId·구간 이름·방향·상태·검증 근거를 반영하고 DEVELOPMENT·STORY의 영향받은 계약을 갱신한다. 현재 진행 인계는 [CONTINUE_STATE.md](CONTINUE_STATE.md), 배정은 [PROJECT_STATE.md](PROJECT_STATE.md)의 규칙을 따른다.
- 이번 회차는 문서 전용이다. 기존 관동 재개 위치·다음 구현 작업·마지막 통합 QC·구현 회차 수를 유지한다.
